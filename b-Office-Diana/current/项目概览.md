# HistoryDiana 项目概览

更新日期：2026-08-13

## 一句话定义

HistoryDiana 是 OneHistory 的 **AI 侧常驻工作区**：托管跨项目公共定义，
并以 `diana` 域的只读指令提供工作树巡检、小工具、MCP 工具中继，以及按 z 通道查看已发布说明书。

## 定位

与 HistoryMercury 对称：

- **Mercury 是人的翻译官**：桌面活动坞、全局快捷键、命令工作台，让人快速驱动系统。
- **Diana 是 AI 的翻译官**：公共定义、工作树巡检、工具中继、z 文档通道，让 AI 快速看清并操作整个体系。

Diana 不进入用户日常界面（`ui: false`），只提供指令与文档入口。

## 目标与边界

### 目标

1. 托管 [`b-Office-OneHistory/`](../../b-Office-OneHistory/)：OneHistory 大块定义、
   跨项目命名规范，以及指向 `diana.docs.catalog` 的入口。
2. 提供 AI 常用的只读能力：工作树巡检（`diana.project.*`）、
   小工具（`diana.kit.*`）、MCP 工具中继（`diana.relay.*`）、
   按 z 通道读说明书（`diana.docs.*`）。
3. 承载**可复用的发布流程**：调用模块自己的候选构建，统一执行测试、把 package Markdown
   写入 `z-*/docs/` 并正式提升。
4. 通过 `diana.project.manifest/docs/align` 为 Janus、Mercury、Minerva、Vulcan 提供统一开发对齐入口。

### 边界

- 不提供 UI 页面，不注册窗口，不参与用户日常交互。
- 消费文档权威源永远在各自仓库的 `b-Office/package/`；已发布正文只在对应 `z-*/docs/`。
  Diana 不保存正文副本。跨项目读取必须先执行 `diana.docs.catalog`，把索引留在对话中。
- 日常巡检指令不写入别的项目。只有用户显式运行已登记发布流程时，脚本才可写候选区和模块 z
  快照；正式提升另需 `-Publish`。

## 依赖

- **HistoryVulcan 宿主**：正式运行与开发均为 3.11.2；Core 公开面自 3.9.0 起冻结。
- **HistoryMercury**：正式模块与开发源码均为 4.5.0。
- **.NET SDK 9.0.315**，目标框架 `net8.0-windows`。

## 与其他项目的关系

Diana 的运行时指令只**读取**别的项目；集中发布脚本是用户显式调用的离线维护工具，
只写入登记模块的候选区和正式 z。
别的项目不依赖 Diana 的代码；它们依赖的是 Diana 托管的公共定义，以及经 MCP 暴露的 z 文档通道。
