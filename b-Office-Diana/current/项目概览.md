# HistoryDiana 项目概览

更新日期：2026-08-15

## 一句话定义

HistoryDiana 是 OneHistory 的 **AI 侧常驻工作区与模块开发管线**：统一管理 AI 工作区、模块发布和跨项目 MCP 读取，
并以 `diana` 域提供隔离工作树、候选构建与试用、正式发布、项目巡检、MCP 中继和 z 文档通道。

## 定位

与 HistoryMercury 对称：

- **Mercury 是人的翻译官**：桌面活动坞、全局快捷键、命令工作台，让人快速驱动系统。
- **Diana 是 AI 的翻译官**：隔离开发、候选验证、发布编排、项目巡检、工具中继和
  z 文档通道，让 AI 能按同一合同开发整个模块体系。

Diana 不进入用户日常界面（`ui: false`），只提供指令与文档入口。

## 目标与边界

### 目标

1. 提供 AI 常用的只读能力：工作树巡检（`diana.project.*`）、
   小工具（`diana.kit.*`）、MCP 工具中继（`diana.relay.*`）、
   按 z 通道读说明书（`diana.docs.*`）。
2. 承载**可复用的发布流程**：调用模块自己的候选构建，统一执行测试、把 package Markdown
   写入 `z-*/docs/` 并正式提升。
3. 通过 `diana.project.manifest/docs/align` 为 Janus、Mercury、Minerva、Vulcan 提供统一开发对齐入口。
4. 通过 `diana.worktree.* → diana.release.* → diana.trial.*` 提供模块开发闭环，并以
   `package/模块开发手册.md` 作为新 AI 的唯一流程入口。

### 边界

- 不提供 UI 页面，不注册窗口，不参与用户日常交互。
- 消费文档权威源永远在各自仓库的 `b-Office/package/`；已发布正文只在对应 `z-*/docs/`。
  Diana 不保存正文副本。跨项目读取必须先执行 `diana.docs.catalog`，把索引留在对话中。
- `project`、`kit`、`docs` 及各类查询命令只读；八条写命令按 MCP `standard` 暴露并显式列名。
- 工作树候选只能构建和试用，不能正式促级；正式提升只从主树发生且必须显式 `publish=true`。
- 模块主线是基线、合并目标和正式发布来源，不是 AI 日常编辑区；AI 的真实修改长期只发生在
  Diana 管理的 `F:\ai工作区` 分支工作树中。Diana 自身主线修改是唯一例外。
- Diana 不隐式 merge、commit、push、建 PR 或部署未登记项目。

## 主要交付物

| 交付物 | 权威位置 | 完成判据 |
| --- | --- | --- |
| 模块产物 | `z-HistoryDiana/` | dll + xml + manifest + SHA256SUMS，校验一致 |
| 项目合同 | `b-Office-Diana/current/` | 四份现行文档与实现一致 |
| 集中发布脚本 | `b-Code/Publish-OneHistoryModule.ps1` | 候选、测试、哈希、写入 docs、正式提升按事务完成 |
| z 文档查看器 | `diana.docs.catalog` 与 `diana.docs.<域>` | catalog 文本必须出现在对话中；通道随 z 文件夹扩展 |
| AI 工作区 | `diana.worktree.*` | 隔离分支、来源与意图可见；闲置与回收有门禁 |
| 候选试用 | `diana.trial.*` | 候选只进私有内存命令表，不进入正式发现或 MCP |
| MCP 发布面 | `diana.release.*` | 工作树只跑候选；主树才可正式提升；状态可跨热重载追踪 |
| 开发手册 | `b-Office-Diana/package/模块开发手册.md` | 新 AI 能从入口文档还原完整开发流程和安全边界 |

## 依赖

- **HistoryVulcan 宿主**：当前运行命令手册版本为 `3.11.3`；为 Diana 提供模块 API、命令注册和 MCP 投影。
- **.NET SDK 9.0.315**，目标框架 `net8.0-windows`。

## 与其他项目的关系

Diana 的巡检与文档指令只读；worktree、trial、release 和 relay.call 是显式写能力。
集中发布只写登记模块的候选区和正式 z，工作树模式不能写正式 z。
别的项目不依赖 Diana 的代码；它们通过 Diana MCP 读取正式 z 文档通道。
