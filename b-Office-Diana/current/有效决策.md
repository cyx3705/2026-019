# HistoryDiana 有效决策

## DEC-001 由 StudioTools 改名为 HistoryDiana，定位为 AI 常驻工作区

- 状态：已接受
- 日期：2026-08-10
- 决策：项目 `2026-019-Studio工具箱` 改名为 `2026-019-HistoryDiana`（目录与分支同名），
  模块 `StudioTools` 改名为 `HistoryDiana`，指令域改为 `diana`。
  定位从"零散工具集合"转为 **AI 侧常驻工作区**，与 Mercury（人的工作区）对称。
- 原因：这些工具的真实使用者是 AI，不是最终用户；散落的 `ToolKit.*` / `ProjectPulse.*` /
  `ToolRelay.*` 三个 PascalCase 两段式前缀既不符合三段式规范，也无法表达它们同属一个工作区。
- 后果：
  - 目录、分支、裸仓 worktree 管理目录三处同步改名，用
    `git worktree move` + `git worktree repair` 完成，不手工只改目录。
  - `z-StudioTools` 退役，正式快照改为 `z-Publish`。
  - 旧指令名 `ToolKit.*` / `ProjectPulse.*` / `ToolRelay.*` 一次作废，不留别名。

## DEC-002 指令收敛为 project / kit / relay 三类

- 状态：已由 DEC-009 扩展；三类结论不再代表当前命令全集
- 日期：2026-08-10
- 决策：当前 13 条指令归入三类——`project` 工作树巡检与四项目对齐 6 条、`kit` 小工具 4 条、
  `relay` MCP 中继 3 条。原 `text` / `identity` / `time` 三个类合并为 `kit`。
- 原因：`text` 2 条、`identity` 1 条、`time` 1 条，各自单开一个类只会让类清单变长而不增加信息。
  它们的共性很清楚：无副作用的一行计算。
- 后果：`diana.kit.sha256 / base64 / guid / now`；project 类新增 `manifest / docs / align`。
  这三类仍保留，但当前另有 docs / worktree / trial / release，完整边界见 DEC-009。

## DEC-003 恢复被误删的 ToolKit 与 ToolRelay 能力

- 状态：已接受
- 日期：2026-08-10
- 决策：改名过程中这两个模块的源文件被删且能力未合并到任何地方，共丢失 7 条能力。
  本次全部恢复并按 DEC-002 归类。
- 原因：MCP 中继解决的是**工具目录快照过期**问题——AI 会话持有的工具清单是任务开始时的
  旧快照，模块热重载后与实际可见工具不一致；中继每次现查现调，绕开旧快照。
  这正是 AI 工作区最需要的能力，删掉与 Diana 的定位直接矛盾。
  小工具组同理，是 AI 高频使用的零成本计算。
- 后果：`OhsmcpClient` 随中继迁入，命名空间改为 `HistoryDiana`。

## DEC-004 公共文档区只放索引，不放副本

- 状态：已由 DEC-005、DEC-007、DEC-013 取代；仅保留背景
- 日期：2026-08-10
- 决策：`b-Office-OneHistory/` 保存 OneHistory 大块定义、命名规范与**消费文档索引**；
  各项目消费文档的权威源仍在各自仓库，本区不保存任何副本。
  Diana 自身合同拆到 `b-Office-Diana/`，与公共区分开。
- 原因：这套体系里反复出问题的都是同一件事——同一事实存多份，改一处漏一处。

- 后果：需要"一个地方看全部"时用索引跳转；需要离线快照时由发布脚本生成，不手工维护。
- 替代条件：若将来出现离线消费场景（无法访问其他 worktree），再引入**生成式**镜像，
  且必须由脚本产出并带来源提交号，不得手工编辑。

## DEC-006 先部署后提交；换模块不关宿主

- 状态：已接受
- 日期：2026-08-13
- 取代：DEC-005 中「脏源发布需独立显式开关」的默认拒绝。
- 决策：集中发布默认从当前工作树构建并提升；`z-*`（含 `docs/`）是发布产物，
  应与源码在部署成功后一次性提交。需要从干净 HEAD 复现时才使用 `-RequireCleanSource`。
  模块提升在正式宿主运行时原地覆盖 z 目录并调用 `vulcan.module.reload`，不得停止 Vulcan。
  只有替换 `z-Publish/host/HistoryVulcan.exe` 时才按正式路径停进程。
- 原因：先提交再部署会把 z 留在第二次提交里，工作树必然再脏一次；
  目录重命名会拆掉热重载监听，关宿主则把本来的内存加载设计变成一次完整冷启动。
- 后果：未提交源变更时工作树为脏是诚实状态；发布脚本在成功后提示应提交的路径。

## DEC-007 消费文档进入 z；Diana 只提供按通道的查看器

- 状态：已由 DEC-013 取代；z/docs 与 MCP 通道规则仍有效

- 取代：DEC-005 把正文镜像到 `b-Office-OneHistory/消费文档/`；DEC-006 中「提交 Diana 消费文档镜像」的产物清单。
- 决策：各项目 `b-Office/package/*.md` 在集中发布时写入该项目 `z-*/docs/`，并重写 `SHA256SUMS`。
  Diana 删除正文副本。跨项目读取只走 Vulcan 上的 `diana.docs.*`：
  `diana.docs.catalog` 现场扫描所有含 SHA256SUMS 的 `z-*`，把通道与文件名写进对话；
  每个 z 文件夹对应一条 `diana.docs.<域>`，省略 `file` 只列出本通道，带 `file` 才读一篇。
  `b-Office-OneHistory/` 只保留定义、命名规范和指向 catalog 的入口，不维护文件表。
- 原因：手维护清单和 Diana 副本都会漂移；一次性读完全部文档会撑爆上下文。
  索引必须出现在对话里才是当场事实。
- 后果：多一个 z 文件夹就多一条通道（附着时登记；新 z 出现后 `vulcan.module.reload`）。
  只读 Markdown/txt，且必须在 SHA256SUMS 内、路径不越出 z、不超过 512 KiB。

## DEC-009 AI 工作区、候选试用和发布成为 Diana 原生命令面

- 状态：已接受
- 日期：2026-08-15
- 取代：DEC-002 的“三类边界”以及“除 relay.call 外全部只读”的旧描述。
- 决策：Diana 命令面扩展为 `docs / kit / project / relay / release / trial / worktree` 七类。

## DEC-010 候选只在工作树验证，正式促级只从主树

- 状态：已接受
- 日期：2026-08-15
- 决策：`diana.release.start worktree=<路径或名称>` 底层转为 `-SourceWorktree <绝对路径>`，
  与 `publish=true` 互斥。正式 Clio z 只能从主树 `-Publish` 写入；工作树无 `-Publish` 时把已验证
  候选写入该树自己的 `z-*`（宿主不扫描）。一轮结束的提交与合并见 DEC-015，不再要求 squash/no-commit
  后再从主树二次正式促级。
- 原因：直接发布工作树产物无法由主树复现；先生成最终源码提交再部署又会在部署失败时留下
  “已经发布”的错误历史。未提交主树 + 已验证候选兼顾可复现性与 DEC-006 的先部署后提交。
- 后果：工作树可有开发提交；正式 Clio z 仍只能从主树 `publish=true` 写入。`worktree.remove`
  默认保护未合并提交并保留分支。commit / merge 的用户入口见 DEC-015。

## DEC-011 MCP 暴露采用 readonly / standard 两级，候选命令不直接投影

- 状态：已接受
- 日期：2026-08-15
- 决策：Diana 模块声明 `mcpExposure: standard`。只读描述符投影为 `readonly`，DEC-009 的八条写命令
  投影为 `standard`；不登记 `dangerous` 或 `hidden`。候选模块的私有命令表不进入宿主正式注册表和
  MCP 工具表，只能通过 `diana.trial.call` 这个 standard 入口调用。

- 后果：运行时 standard 策略下的工具总数随固定命令与现场 z 通道变化；DEC-015 起固定命令为 25 条、
  写命令 7 条。动态通道变化时总数不写进测试常量。

## DEC-012 AI 长期工作区只存在于 Diana 管理的 F 盘

- 状态：已接受
- 日期：2026-08-15
- 决策：AI 不把 Janus、Mercury、Minerva、Vulcan 等模块源码主线当作日常编辑目录。
  模块主线只承担源码基线、分支合并目标和正式发布来源；AI 通过 Diana 拉取分支，真实修改、开发提交、
  候选构建与试用均发生在 `F:\ai工作区` 下的 Diana worktree。验证完成后，再把分支改动带回主线并从主线正式促级。
  修改 Diana 自身主线是唯一例外。
- 原因：统一 AI 工作区位置和生命周期，避免不同项目各自开 worktree、直接污染主线或绕过 Diana 门禁，
  也让新 AI 能从一个入口发现所有模块开发操作。
- 后果：所有模块项目的 AI 开发合同都应把 Diana MCP 作为工作区入口；直接进入模块主线编辑属于流程违规，
  即使最后产物与标准管线一致，也不算规范开发过程。

## DEC-014 `ui=true` 试用前先卸同名正式模块

- 状态：已退役，由 DEC-025 取代
- 日期：2026-08-16
- 决策：`diana.trial.load ui=true` 在中继 `vulcan.module.trialui.load` 之前，若宿主已装载同名正式模块，
  先执行 `vulcan.module.unload` 释放工具窗口 Id；该次试用卸完且没有仍占用该位置的试用后，

- 后果：人工验收 `ui=true` 需要 HistoryVulcan **3.11.5**；同一时刻只应有一份占用正式模块位置的 UI 试用。
  Diana 版本提升到 `1.10.3`。

## DEC-015 一轮结束只留 cycle 与 merge 两条写命令

- 状态：部分退役，命令数量与旧 trial 子命令由 DEC-025 取代
- 日期：2026-08-16
- 取代：DEC-010 / DEC-011 中「Diana 不提供 commit、merge」以及手册 squash/no-commit → 主树二次
  `publish=true` 的收尾顺序。DEC-010 的 XOR（工作树不得 `publish=true`）与「试用只进内存」仍有效。
- 决策：用户可见的收尾只有两条写命令。
  1. `diana.release.cycle name=… msg=… [worktree=…] [ui=true]`：等待同一发布管线结束，再提交本树。
     主树省略 `worktree` 时走 `publish=true`（正式 Clio z + 热重载）后提交；工作树写入该树 `z-*`
     后提交，再 `trial.load`（默认 `ui=true`，先卸同名正式模块）。试用失败不回滚已经成功的提交。
  2. `diana.worktree.merge project=… name=…`：工作区必须干净；主树必须在 `main`；快进优先否则
     `--no-edit` 合并；先卸该工作区试用，合并后再 `vulcan.module.reload`，最后强制回收工作区
     （分支保留）。合并把工作区里已验证的源码与 `z-*` 一并带上主线，不再从工作树二次正式促级。
  `release.start`、`worktree.remove` 不再登记为 MCP，只作 cycle/merge 的内部方法。
  当时 `trial.load` 也不登记，后由 DEC-016 恢复为看一眼候选的 MCP。
  `status/log`、`trial.list/call/unload` 仍登记：前者只读排障，后者在 cycle 之后调用或提前卸试用。
  不提供 push 或建 PR。`trial.load` 是否单独登记 MCP 见 DEC-016。
- 原因：AI 一轮结束后若仍要手工 status、trial、commit、unload、remove，收尾就会在审批后再次卡住。
  工作区 z 是候选槽不是第二套装载器；正式 Clio z 仍只允许主树 `publish=true` 或合并带过来的 z。
- 后果：固定命令 25 条，写命令 7 条（23 readonly / 7 standard + 现场 z 通道）。Diana 版本仍为
  `1.10.4`（尚未正式发布）。HistoryDiana 自身 cycle 若触发热重载，等待可能中断，提交仍在分离子进程收尾。
  其中「trial.load 不再登记 MCP」已被 DEC-016 取代。

## DEC-016 `diana.trial.load` 是看一眼候选的唯一 MCP

- 状态：已退役，由 DEC-025 取代
- 日期：2026-08-16
- 取代：DEC-015 中「`trial.load` 不再登记为 MCP，只作 cycle 内部方法」这一条。cycle/merge
  仍是提交与并回主线的收尾入口；`release.start`、`worktree.remove` 仍不登记。
- 决策：把「卸同名正式模块」和「临时注册候选」收进一条用户可见命令 `diana.trial.load`。
  1. `path` 必填，指向任意含 `module.manifest.json` 的目录（工作区 `z-*`、候选目录均可）。
  2. 默认 `ui=true`：先 `vulcan.module.unload` 同名正式模块（跳过 HistoryDiana），再内存装载，
     并由前端建验收界面。只验调用面时显式 `ui=false`。
  3. 不改 `vulcan.module.roots`、不写 AppData 模块槽、不写正式 Clio z。看完 `diana.trial.unload`。
  4. 未提交、不想跑门禁时不要为了看一眼去 `cycle`；cycle 提交后仍内部走同一装载路径。
- 原因：把 load 藏进 cycle 之后，AI 为了看未提交候选会去拼发现根、拷 AppData、中继不可见的
  `vulcan.module.unload`，回合长、还容易把正式装载面改坏。一条 MCP 就能表达真实意图。
- 后果：固定命令 26 条，写命令 8 条（23 readonly / 8 standard + 现场 z 通道）。Diana 版本提升到
  `1.10.5`，已正式写入 `z-Publish`。

## DEC-017 回收工作区前必须卸尽试用（含前端残留）

  1. 按模块名和工作区路径卸掉 Diana 进程内的试用装载；
  2. 即使静态试用表已空（例如 Diana 自身热重载丢了字典），仍向前端发
     `vulcan.module.trialui.unload`，拆掉占用工作区 DLL 的验收界面；
  3. 触发可回收 ALC 回收并重试删除目录；
  4. 与 git 交换工作区路径时使用 UTF-8，避免 `F:\ai工作区` 被读成乱码后 `worktree remove` 指错目录。
  顺序为：卸试用 → 合并 → 回收目录 → 再 `vulcan.module.reload` 装入主线 z。
- 原因：试用 DLL 锁在工作区里时，merge 会快进成功却删不掉目录；git 用系统编码读 porcelain
  时中文根会变成「不是一个工作树」。这两件事都会让「合并删除」看起来像忘了卸测试模块。
- 后果：Diana 版本提升到 `1.10.6`，已正式写入 `z-Publish`。

## DEC-018 热重载 Diana 后仍须卸掉残留试用 ALC
