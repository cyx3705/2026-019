# HistoryDiana 技术合同

本文件合并当前有效的需求与架构。关键决策单独保存在 `有效决策.md`；已失效内容移入
`../history/`，不得继续作为实现依据。

## 现行需求

### REQ-001 无自有 UI 模块

- 目的：Diana 服务于 AI，不占用用户的界面空间。
- 要求：`module.manifest.json` 的 `ui` 恒为 `false`；程序集不得包含实现
  已移除 `IUiModule` 的公开类型；不注册任何窗口。`diana.view.*` 只能观察现有 HistoryVulcan 前端，
  不因此取得 UI 生命周期或向前端注入控件。
- 验收：Smoke 断言程序集中不存在已移除的 `IUiModule` 类型或 UI 生命周期类型。

### REQ-002 AI 工具集中归属、指令分类与只读性

- 目的：让 AI 通用工具有唯一归属，同时保证巡检整个项目库时不会写坏任何工作树。
- 要求：
  1. 全部指令使用 `diana.<类>.<方法>` 三段式，宿主按模块名归一化为 `diana` 域。
  2. 类恰有七个：`log`（控制台内存日志）、`host`（活宿主装载观察）、`project`（项目巡检与对齐）、
     `kit`（小计算）、`relay`（MCP 中继）、`docs`（z 说明书）、`view`（前端图形观察）。
     模块开发闭环不在本模块。
  3. 写命令必须显式列名，当前恰为两条：`diana.relay.call` 与 `diana.view.capture`。后者只写
     Diana 运行态截图目录。其余全部声明 `Readonly`。
     不得再登记 `diana.worktree.*`、`diana.release.*`、`diana.trial.*`。
  4. 指令由 `IModuleContext.RegisterCommands` 显式登记，不使用反射投影
     ——反射投影会按类型名生成两段式命令（旧 `ToolKit.Sha256` 即如此）。
  5. `diana.docs.catalog` 与 `diana.docs.read` 恒登记；`read` 的域和文档每次执行时从当前 `z-*` 实时解析，新增模块无需新增命令或重新编译 Diana。
     通道数量随 z 文件夹增减，Smoke 不断言运行时总命令数。
  6. 面向 AI、跨项目且不属于业务领域合同的新工具默认由 Diana 拥有。业务模块继续拥有自己的领域命令；
     Diana 只提供发现、中继和通用工具，不复制领域实现。唯一基础设施例外见 REQ-006。
- 验收：Smoke 断言固定命令、域、七个类、两条写命令、catalog 索引文本与只读性；通道随夹具 z 出现；
  项目合同检查 README、manifest、概览和模块API 使用同一归属口径。

### REQ-012 AI 前端图形查看器

- 目的：让 AI 以真实像素核对 HistoryVulcan 前端变化，而不是仅根据命令数据或日志猜测布局。
- 要求：
  1. `diana.view.windows` 只列出当前用户会话中进程名为 `HistoryVulcan` 的可见顶层窗口，返回标题、
     进程、窗口句柄、客户区坐标与原始像素尺寸；不得列出其他应用窗口。
  2. `diana.view.capture` 接受 `windows` 返回的句柄；省略时选择客户区面积最大的可见窗口。
     最小化窗口明确失败，不自动激活、还原或改变前端状态。
  3. 捕获客户区原尺寸像素，优先 `PrintWindow`，失败时回退窗口 DC `BitBlt`；PNG 只写入
     `%AppData%\\HistoryVulcan\\HistoryDiana\\captures`，返回绝对路径、宽高、字节数、SHA-256、
     实际采集方式、采样颜色数及明暗比例。目标不是 HistoryVulcan 或句柄已失效时必须拒绝。
  4. `view.capture` 因写入运行态 PNG 标为非只读；不得把截图写入模块运行包、项目仓库或 z 快照。
- 验收：Smoke 验证两条命令、安全分级及 PNG 编码/解码；热重载后对真实前端执行捕获，复算尺寸、
  SHA-256，并检查 `NonUniform=true`，再由 AI 打开 PNG 做视觉核对。

### REQ-014 活宿主装载观察

- 目的：让《模块开发手册》第四节的热重载判据能在 MCP 面完成。宿主的 `vulcan.module.*` 整类
  都不投影到 MCP——写操作按策略隐藏，只读的 `list` / `ready` 被一起挡在外面——AI 每一轮都得
  跳出 MCP 去跑 Console CLI 才能确认「装进去了没有」。
- 要求：
  1. 新增 `host` 类和两条只读命令。`diana.host.modules` 转发宿主 `vulcan.module.list`；
     `diana.host.ready` 转发 `vulcan.module.ready`。两条都只经 `IModuleContext.Bus` 在当前进程内调用，
     不引用宿主内部类型，不持有上一次解析到的实例，不经 MCP 或 HTTP 回环再入。
  2. `diana.host.modules` 返回 `capturedAt`、`moduleCount`、`attachedCount`、`attachFailureCount`
     与 `modules[]`；每个模块给出 `name`、`version`、`instanceId`、`commandCount`、`attached`、
     `ui` 和 `attachFailures[]`。`attachFailures` 原文照抄，那是「界面消失但命令还在」一类故障的
     直接证据。**不得回显运行槽、源路径或 manifest 绝对路径**——核对热重载不需要它们。
  3. `name=` 按模块名大小写不敏感精确匹配。目标未装载时明确失败并指向不带 `name` 的完整目录，
     不返回空集合冒充成功。
  4. 宿主未登记该指令、返回结构不受支持或非数组时明确失败；不得回退截图、磁盘日志或 CLI 子进程。
  5. 两条命令恒为 `Readonly=true`。`host` 类不得新增任何写命令：安装、重载、卸载仍只由宿主
     `vulcan.module.install` 与冻结的 `vulcan.dev.*` 拥有，见 REQ-006。
  6. `diana.host.ready` 返回 `false` 表示本轮装载尚未接完，是可重查的正常状态，不是失败。
- 验收：Smoke 用可替换的宿主提供者覆盖强类型返回、大小写不一致的属性名、`attachFailures` 原文、
  `name` 过滤、未装载模块、提供者缺失和非布尔就绪值，并断言两条命令只读、消息不含运行槽路径。
  真实宿主验收在一轮 `vulcan.dev.submit` 之后执行，比对该模块 `instanceId` 已变、
  Aurora `commandCount` 仍大于 0。

### REQ-003 巡检只读且限定在已登记工作树

- 目的：防止路径穿越与对无关目录的扫描。
- 要求：`diana.project.*` 只接受**项目库根下的已登记项目名**，不接受任意路径；
  项目必须是 HistoryClio 独立 Git 仓库（`.git` 目录）或仍带 worktree 指针文件的遗留目录。
  `includeGenerated=false` 时跳过生成目录（`bin`、`obj`、`.vs`、`node_modules`、`z-Publish`、
  `artifacts` 等）；只有显式传 `includeGenerated=true` 才纳入。
     库根由 Diana 运行时解析器读取 `HISTORYCLIO_ROOT`，未设置时使用宿主默认的 `C:\OneHistory\HistoryClio`；不从 `IModuleContext` 读取宿主设置。
- 验收：Smoke 用临时独立仓验证三条指令可执行且结果结构正确。

### REQ-004 跨项目说明书只从各自 z 经 Diana MCP 消费

- 目的：让任何项目里的 AI 都能取到各模块正式发布的说明书，同时避免在 Diana 再造集中副本。
- 要求：
   1. 消费文档权威编辑源永远在各自仓库的 `b-Office/package/`；发布成功后写入该项目
      `z-Publish/HistoryX-vX.Y.Z/docs/`，由 `SHA256SUMS` 覆盖。Diana 不保存正文副本，也不回退旧发布目录。
  2. 跨项目读取必须先执行 `diana.docs.catalog`，把完整索引留在当前对话，再调用一条
     `diana.docs.read domain=<域>`。省略 `file` 只列出该通道；带 `file` 才读一篇，且仅限 z 内已登记的
     `.md` / `.txt`、路径不越出 z、不经过重解析点、不超过 512 KiB、哈希与 SHA256SUMS 一致。
     发布包 manifest 必须是有效 JSON，身份/版本必须与候选目录一致，且 manifest 本身必须被
     `SHA256SUMS` 覆盖并复算一致；不满足时整个通道不可见，不得退回目录名猜测身份。
     `file` 可以是 catalog 相对路径，也可以是通道内唯一的文件名。
     超过 12 KiB 的正文必须带 `heading=`，否则只返回章节目录，避免整篇灌进对话。
     `heading=` 可以是 Markdown 标题，也可以是 `x.y.z` 版本号（切出该版本的列表项，直到下一条不同版本）。
      长文目录同时列出章节和版本号。当前 Vulcan 5.1.2 消费变更摘要应 `heading=5.1.2`，不要用会吞掉全部历史的
      `heading=主要变化`。
     heading 不存在时最多返回前 20 条章节/版本建议，并提示省略 heading 获取完整目录，不得把长文全部标题塞进错误响应。
  3. Diana 自身的项目合同放在 `b-Office-Diana/`；仓库不得新增集中模块消费文档区。
- 验收：Smoke 验证 catalog 文本含通道命令、按通道列举与单篇读取、拒绝越出 z 的路径；合同检查验证不存在已退役的集中消费文档目录。

### REQ-006 冻结开发管线排除在 Diana 之外

- 目的：避免 AI 工具区与模块开发基础设施出现双入口、循环依赖或发布权限漂移。
- 要求：
  1. Diana 不拥有发布器，不登记 `diana.worktree.*`、`diana.release.*`、`diana.trial.*`，也不得恢复
     `Publish-OneHistoryModule.ps1`、`-Publish`、`-OutputRoot` 或 `-SourceWorktree` 集中发布入口。
     Diana 不构建、不提升、不安装任何模块或宿主快照。
  2. 已冻结的模块开发闭环只由 HistoryVulcan Console CLI 提供：
     `vulcan.dev.start` → `vulcan.dev.submit` → `vulcan.dev.finish`。这些命令不投影到 MCP，
     不得通过 `diana.relay.call` 绕行；Diana 自身开发也遵守同一边界。登记表只在宿主
     `b-Code-Eng/pipeline/module-publish.manifest.json`。已登记模块：
     `HistoryDiana`、`HistoryJanus`、`HistoryMercury`、`HistoryMinerva`、`HistoryAurora`、
     `HistoryPortunus`；`HistoryVulcan` 是 `kind=host`，禁止走 `vulcan.dev.*`，写入 z 只用
     `vulcan.release.cycle`。
  3. `b-Code/` 只保留本仓合同检查和本模块候选辅助脚本；宿主管线不调用 Diana 脚本。
     各模块本地 `Build-*Package.ps1` 若存在，必须写出与宿主相同的版本化目录，不得再为
     「Diana 传入 OutputRoot」保留扁平根。
  4. 快照形状由宿主管线写入，Diana 文档通道只读取，不生成：

      | | module | host |
      | --- | --- | --- |
      | 快照清单 | `module.manifest.json`，身份键 `name` | `manifest.json`，身份键 `product` |
      | 当前候选根 | `z-Publish/HistoryX-vX.Y.Z/` | `z-Publish/host/` |
      | 目录结构 | 运行文件平铺，说明书在 `docs/` | 当前根含 `host/`、`docs/`、`manifest.json`、`SHA256SUMS`；旧版本只在 `history/` |
      | SHA256SUMS | 带 `/` 的相对路径，递归覆盖 | 带 `/` 的相对路径，递归覆盖 |

     `z-Publish/` 根上除 `history/` 与当前一个 `HistoryX-vX.Y.Z/`（宿主则是平铺 `host/`）外不得再摊运行文件。
  5. 不得再以「脚本不接受 `-OutputRoot`」为由把模块排除在宿主登记表外。
- 验收：运行时 Diana 命令面不含开发管线类；宿主 CLI 自发现列出三条开发命令且 MCP 工具表不包含它们；
  仓库不存在 `Publish-OneHistoryModule.ps1`；各已登记模块当前候选可被 `diana.docs.catalog` 按
  `History*-v*`（宿主按平铺 `host/`）发现。

### REQ-005 模块身份单一来源

- 目的：manifest 与 `ModuleInfo` 版本不一致会让宿主**静默跳过整个模块**。
- 要求：`ModuleInfo.Version` 从程序集读取，不写字面量；版本源唯一为
  `b-Code-HistoryDiana/HistoryDianaVersion.props`。
- 验收：Smoke 比对 `ModuleInfo` 与程序集版本。

### REQ-008 项目入口对齐 MCP

- 目的：让已授权的项目维护使用统一身份与入口检查；跨项目消费正文仍走 z 文档通道。
- 要求：
  1. `diana.project.manifest` 只读取已登记工作树的 `project.manifest.json`。
  2. `diana.project.docs` 只读取 manifest 声明的四类现行文档，不接受任意路径，不超过 512 KiB；工具描述明确仅用于已授权维护，不替代跨项目 docs 通道。
  3. `diana.project.align [name=]` 支持指定项目；省略时动态枚举库根直属、非重解析点、带 Git 标记与 project.manifest.json 的目录。逐项报告身份、版本和四类文档入口存在性，不读取正文；坏 manifest 作为失败行返回。
  4. 三条指令全部只读；不得执行任意 Shell，不得写入项目。
- 验收：Smoke 验证命令全集、manifest/document 路径边界和对齐结果结构。

### REQ-009 AI 开发工作区与隔离分支

- 目的：让 AI 长期只在隔离工作区开发，不污染模块源码主线。
- 要求：工作区生命周期由宿主 `vulcan.dev.start/submit/finish` 拥有，不在 Diana 命令面。
  “AI 工具区”是 Diana 的产品定位，“AI 工作区”是 `F:\ai工作区` 下的临时 Git worktree，两者不得混称。
  默认工作区根仍为 `F:\ai工作区`。
- 验收：运行时 `diana` 域不含 `worktree` 类；宿主登记 `vulcan.dev.*`。

### REQ-010 候选与历史包严格重载

- 目的：候选测试和回退使用与正式模块相同的唯一运行槽。
- 要求：装机走宿主 `vulcan.module.install`；Diana 不再转发 `trial.load`。
  写入版本化候选只由宿主 `vulcan.dev.submit` / `finish` 完成。
- 验收：Smoke 断言不登记 `diana.trial.*`。

### REQ-011 AI 工具发现与冻结开发管线

- 目的：新 AI 能从 Diana 发现实时工具，同时明确模块开发只能走宿主 CLI。
- 要求：
  1. `module.manifest.json` 的 `mcpExposure` 为 `standard`；只读描述符投影为 `readonly`，
     `diana.relay.call` 投影为 `standard`。
  2. 开发闭环为 `vulcan.dev.start` → `vulcan.dev.submit` → `vulcan.dev.finish`。
     手册入口在 HistoryVulcan `b-Office/package/模块开发手册.md`。开发管线不走 MCP。
  3. `diana.relay.list/describe/call` 连接当前宿主 loopback MCP 的实时工具目录。默认从
     `%USERPROFILE%\.cursor\mcp.json` 的 `mcpServers.history-vulcan.url` 取地址；只接受
     `http` 回环地址和 `/mcp` 路径，不携带令牌。`HISTORYVULCAN_ENDPOINT` 仅作为显式兼容入口，
     可给同样受限的 URL 或旧 `endpoint.json` 文件。
- 验收：Smoke 验证七类命令、两条写命令、当前 MCP 配置解析和模块命令名投影；项目合同不再要求 Diana 包内模块开发手册。

### REQ-013 原生读取当前控制台日志

- `diana.log.read` 通过当前进程命令总线调用隐藏只读提供者 `aurora.log.snapshot`，每次解析当前
  提供者，不持有 Aurora 类型或实例；详细参数、响应形状和边界见
  [`原生控制台日志查看需求书.md`](./原生控制台日志查看需求书.md)。
- 默认 `minlevel=error`；生产端完成级别、来源、关键字、时间、增量和数量过滤。Diana 校验
  `schemaVersion=1`、字段、计数、排序和 256 KiB 上限后才返回。
- Aurora 在消息进入控制台唯一缓冲前完成敏感文本净化；Diana 不接触原始接收器或未净化参数，
  也不另建一套可能与桌面控制台漂移的脱敏规则。
- 提供者缺失、前端未附着、热重载窗口或未知结构明确失败；不回退截图、磁盘、MCP relay 或网络。
- `truncated=true` 只表示本次结果不完整，成因有两个：生产端按 `limit` 截断，或触及 256 KiB 上限。
  调用方不能只用计数区分条数与字节上限；应按 nextAfter 分页，Diana 不解释成单一成因。

### 质量属性

| 编号 | 属性 | 可度量要求 | 验收方式 |
| --- | --- | --- | --- |
| QA-001 | 可装载性 | 宿主发现 1 个模块；固定七类命令；文档通道数随现场 z 变化 | Smoke |
| QA-002 | MCP 安全 | 写命令仅 `relay.call` / `view.capture`，其余全部只读 | Smoke + 运行时手册 |
| QA-003 | 供应链 | z 快照每个文件都被 SHA256SUMS 覆盖 | 校验脚本 |
| QA-004 | 文档可追溯 | manifest 与已发布 Markdown 均被 SHA256SUMS 覆盖；路径不经过重解析点；catalog 现场扫描 | Smoke + 发布后复核 |
| QA-005 | 发布原子性 | 含 docs 的模块 z 一次提升成功，否则恢复旧版本 | 宿主 `vulcan.dev.submit` 故障路径 + 发布后复核 |
| QA-006 | 开发隔离 | 工作树候选不能正式促级；正式发布只从主树发生 | 宿主 `worktree` 与 `publish=true` 互斥 + 集成验证 |
| QA-007 | 可发现性 | 新 AI 从 README/manifest 能定位 Diana 工具区及宿主 CLI 例外 | 项目合同检查 + 文档复核 |
| QA-010 | 归属唯一性 | AI 通用工具默认归 Diana；领域工具和冻结开发管线各自保留唯一所有者 | 文档一致性检查 + 架构审查 |
| QA-008 | 图形真实性 | 截图保持客户区原始尺寸、SHA 可复算且非单色 | Smoke + 真实前端捕获 |
| QA-009 | 可修正失败 | 可预期错误返回具体原因且建议限长，不退化为异常类型名或无界标题清单 | Smoke + MCP 负向用例 |

## 系统架构

| 组件 | 路径 | 职责 |
| --- | --- | --- |
| 模块入口 | `b-Code-HistoryDiana/ModuleInfo.cs` | 模块身份，版本取自程序集 |
| 命令注册 | `b-Code-HistoryDiana/HistoryDianaCommands.cs` | 唯一注册入口，登记七类指令 |
| 巡检 | 同上 | `diana.project.summary/recent/largest` |

### REQ-015 有界观察基线与对比（2.6.0）

- `diana.host.observe name= [baseline=]` 为只读命令，顺序读取日志游标、模块目录和就绪状态。
  返回 `atomic=false`：这些是分次快照，不能冒充宿主原子事务或 submit 成功回执。
- 基线令牌为调用方持有的版本化 Base64 JSON，最多 64 KiB，不持久化、不缓存模块引用、不含日志正文或磁盘路径。
  令牌校验结构、版本、目标、时间、序号与重复模块；目标匹配不区分大小写。令牌是比较输入，不是可信授权凭证。
- 使用日志 `newestSequence` 划线，避免默认 Error 筛选使 `nextAfter` 停在旧错误上。
  比较实例变化、模块增删、指令数下降与附着退化；目标缺失明确提示，实例未知返回 null，不推断成功。
- 前端实例变化后按基线时间重读，标记旧内存日志无法恢复；查询过程中再次变更、缓冲缺口和截断均标记
  `logsComplete=false`。截断结果使用 `diana.log.read` 翻页，不能用新的 baselineToken 替代旧错误分页游标。
- 提供者失败保留其他可取得证据并列入 issues；没有模块或日志数据不产生新令牌。
  `pipeline.status=unavailable` 明确说明现有接口不能提供管线阶段、等待原因与完成状态，指向 CLI 回执及宿主手册。
- 验收：Smoke 覆盖首轮基线、同实例、实例变化、模块消失/退化、坏令牌、跨目标、前端重启及提供者缺失；候选热重载后实调。

### REQ-016 文档回执与工具说明（2.6.0）

- `docs.read` 全文与章节正文仅保留在 `Data.Content`，Message 为短摘要，Content/SHA/版本字段不删。
  catalog 保留完整可读索引，长文保留标题目录。网关的 JSON 文本与 structuredContent 兼容投影不由 Diana 改写。
- catalog 不硬编码宿主当前版本；relay 示例使用真实 Diana 只读工具，不再引导旧 worktree 命令。
- 验收：Smoke 从 Data.Content 验证章节范围，断言 Message 不再重复正文；运行时核对工具描述。- relay.call 对普通 JSON 优先原样解析；仅在解析失败且对象开头为转义引号时尝试解码一层 JSON 字符串转义。
  保留 64 KiB 和对象类型限制，防止客户端把引号保留为转义文本导致所有带参数中继失败。
  Smoke 覆盖 Unicode、换行、字面反斜杠、两种引号转义和非法/超限对象。
- AI 实验收补充：observe 摘要和顶层数据显式列出 errorCount、regressionCount；基线标为历史错误，比较标为新增错误。
  issues 只代表证据完整性等提示，不等于错误数量。Smoke 断言有错误而 issues 为空时摘要仍显示新增错误。
