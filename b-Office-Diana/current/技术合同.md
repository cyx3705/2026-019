# HistoryDiana 技术合同

本文件合并当前有效的需求与架构。关键决策单独保存在 `有效决策.md`；已失效内容移入
`../history/`，不得继续作为实现依据。

## 现行需求

### REQ-001 无 UI 模块

- 目的：Diana 服务于 AI，不占用用户的界面空间。
- 要求：`module.manifest.json` 的 `ui` 恒为 `false`；程序集不得包含实现
  `IUiModule` 的公开类型；不注册任何窗口。
- 验收：Smoke 断言程序集中 `IUiModule` 实现数为 0。

### REQ-002 指令分类与只读性

- 目的：AI 巡检整个项目库时必须保证不会写坏任何工作树。
- 要求：
  1. 全部指令使用 `diana.<类>.<方法>` 三段式，域恒为 `HistoryDiana`
     （归一化后的指令域为 `diana`）。
  2. 类恰有三个：`project`（工作树巡检与四项目对齐）、`kit`（哈希/编码/标识/时间）、
     `relay`（MCP 工具中继）。
  3. 除 `diana.relay.call` 外全部声明 `Readonly`。
     `relay.call` 是唯一写操作，因为它会真正调用目标工具。
  4. 指令由 `IModuleContext.RegisterCommands` 显式登记，不使用反射投影
     ——反射投影会按类型名生成两段式命令（旧 `ToolKit.Sha256` 即如此）。
- 验收：Smoke 断言命令全集、域、三个类与只读性。

### REQ-003 巡检只读且限定在已登记工作树

- 目的：防止路径穿越与对无关目录的扫描。
- 要求：`diana.project.*` 只接受**已登记工作树名**，不接受任意路径；
  扫描时跳过生成目录（`bin`、`obj`、`.vs`、`node_modules` 等）。
- 验收：Smoke 用临时工作树验证三条指令可执行且结果结构正确。

### REQ-004 托管跨项目公共文档区

- 目的：让任何项目里的 AI 都能取到同一份 OneHistory 事实。
- 要求：
  1. `b-Office-OneHistory/` 保存 OneHistory 大块定义、目录与命名规范、消费文档索引。
  2. 消费文档权威编辑源永远在各自仓库；发布成功后允许在 `消费文档/<模块>/` 保存生成式镜像。
     镜像不得人工编辑，必须带模块版本、来源项目、commit、dirty 状态和逐文件 SHA。
  3. Diana 自身的项目合同放在 `b-Office-Diana/`，与公共区分开。
- 验收：公共定义与索引齐备；已发布镜像的 manifest 和逐文件 SHA 全部可复验。

### REQ-006 集中模块发布

- 目的：让各模块保留自己的源码、测试和候选构建逻辑，同时把正式提升和消费文档收口到 Diana。
- 要求：
  1. `b-Code/Publish-OneHistoryModule.ps1` 只接受显式登记的项目；普通 `Kind=module` 的登记与验证步骤
     位于 `b-Code/module-publish.manifest.json`，新增普通模块不需要修改主脚本。已登记：
     `HistoryJanus`、`HistoryMercury`、`HistoryMinerva`（Kind=module）、`HistoryVulcan`（Kind=host）。
  1.1 **两种 Kind 的差异只在快照形状与验证步骤**；普通模块验证步骤由登记表声明，候选构建的调用形状统一为
     `-Configuration Release -OutputRoot <候选目录>`：

     | | module | host |
     | --- | --- | --- |
     | 快照清单 | `module.manifest.json`，身份键 `name` | `manifest.json`，身份键 `product` |
     | 目录结构 | 平铺 | `host/` 与 `docs/` 多层 |
     | SHA256SUMS | 文件名 | 带 `/` 的相对路径，递归覆盖 |
     | 源 manifest | 有，需与版本源对齐 | 无（少一处可漂移） |
     | 验证 | 项目合同 + Smoke + UI Smoke | 单元测试 + 质量门禁 + 公共 API 基线 |
  2. 固定顺序为：构建候选 → 校验候选 SHA → 项目合同 → Smoke → UI Smoke → 暂存文档镜像 →
     原子提升模块 z 与 Diana 文档镜像。
  3. 默认停在候选；正式提升必须指定 `-Publish`。脏工作树默认拒绝，只有显式
     `-AllowDirtySource` 才继续，并把 `sourceDirty=true` 写入镜像清单。
  4. 正式快照与文档镜像任一提升失败时必须回滚两者；旧快照保存在各自 `b-Publish/history`。
- 验收：已登记项目按登记表可独立运行；HistoryJanus、HistoryMercury、HistoryMinerva（module）与
  HistoryVulcan（host）均已跑通，
  z 包与 Diana 文档镜像版本一致且 SHA 可复验。

### REQ-007 Vulcan 发布后修复登录启动

- 目的：Vulcan 正式 Z 路径随版本提升而变化时，后台登录启动项仍指向当前正式宿主。
- 要求：HistoryVulcan 正式提升成功后调用正式快照的 `HistoryVulcan.exe --repair-autostart`；修复失败
  只报告部署后运维警告，不回滚已经验证并提升成功的快照。修复入口必须尊重后台 `svc.autostart`
  设置，显式关闭时不得重新启用。
- 验收：启用时 HKCU Run 的 `HistoryVulcan.Backend` 精确指向当前正式 Z 可执行文件并带
  `--service`；旧 `AppShell.Backend` 被清理，其他启动项不受影响。

### REQ-005 模块身份单一来源

- 目的：manifest 与 `ModuleInfo` 版本不一致会让宿主**静默跳过整个模块**。
- 要求：`ModuleInfo.Version` 从程序集读取，不写字面量；版本源唯一为
  `b-Code-HistoryDiana/HistoryDianaVersion.props`。
- 验收：Smoke 比对 `ModuleInfo` 与程序集版本。

### REQ-008 四项目开发对齐 MCP

- 目的：让 HistoryJanus、HistoryMercury、HistoryMinerva、HistoryVulcan 的 AI 开发会话从同一入口读取项目身份、现行合同和对齐状态。
- 要求：
  1. `diana.project.manifest` 只读取已登记工作树的 `project.manifest.json`。
  2. `diana.project.docs` 只读取 manifest 声明的四类现行文档，不接受任意路径，不超过 512 KiB。
  3. `diana.project.align` 固定检查上述四个项目，报告 manifest 身份、版本和四类文档入口是否存在。
  4. 三条指令全部只读；不得执行任意 Shell，不得写入项目。
- 验收：Smoke 验证命令全集、manifest/document 路径边界和对齐结果结构。

### 质量属性

| 编号 | 属性 | 可度量要求 | 验收方式 |
| --- | --- | --- | --- |
| QA-001 | 可装载性 | 宿主发现 1 个模块并注册 13 条指令 | Smoke |
| QA-002 | 只读安全 | 除 `relay.call` 外全部只读 | Smoke |
| QA-003 | 供应链 | z 快照每个文件都被 SHA256SUMS 覆盖 | 校验脚本 |
| QA-004 | 文档可追溯 | 镜像均由发布脚本生成，含来源 commit/dirty 与逐文件 SHA | 镜像 manifest 复验 |
| QA-005 | 发布原子性 | 模块 z 与文档镜像同时成功，否则恢复旧版本 | 发布脚本故障路径 + 发布后复核 |

## 系统架构

| 组件 | 路径 | 职责 |
| --- | --- | --- |
| 模块入口 | `b-Code-HistoryDiana/ModuleInfo.cs` | 模块身份，版本取自程序集 |
| 命令注册 | `b-Code-HistoryDiana/HistoryDianaCommands.cs` | 唯一注册入口，登记三类指令 |
| 巡检 | 同上 | `diana.project.summary/recent/largest` |
| 小工具 | `b-Code-HistoryDiana/DianaKitCommands.cs` | `diana.kit.sha256/base64/guid/now` |
| 工具中继 | `b-Code-HistoryDiana/DianaRelayCommands.cs` + `OhsmcpClient.cs` | `diana.relay.list/describe/call` |
| 验证 | `b-Code-HistoryDiana/tests/HistoryDiana.Smoke` | 身份、命令全集、只读性、无 UI |
| 公共文档区 | `b-Office-OneHistory/` | 跨项目定义与索引 |
| 集中发布 | `b-Code/Publish-OneHistoryModule.ps1` | 候选构建、测试、正式提升、回滚和文档镜像 |
| 消费文档镜像 | `b-Office-OneHistory/消费文档/` | 生成式只读镜像与来源 manifest |
| 正式消费区 | `z-HistoryDiana/` | 宿主装载的正式快照 |

### 不变量

- 唯一版本源：`b-Code-HistoryDiana/HistoryDianaVersion.props`，当前开发版本 `1.0.0`。
- 宿主基线：HistoryVulcan `3.11.1`；Core 公开面冻结基线为 `3.9.0`。
- 可重建生成物：`bin/`、`obj/`、`b-Publish/`。
- 可重建文档镜像：`b-Office-OneHistory/消费文档/`，只由集中发布脚本写入。
- 正式消费快照：`z-HistoryDiana`，恒为 dll + xml + manifest + SHA256SUMS 四件。
