# HistoryDiana 技术合同

本文件合并当前有效的需求与架构。关键决策单独保存在 `有效决策.md`；已失效内容移入
`../history/`，不得继续作为实现依据。

## 现行需求

### REQ-001 无 UI 模块

- 目的：Diana 服务于 AI，不占用用户的界面空间。
- 要求：`module.manifest.json` 的 `ui` 恒为 `false`；程序集不得包含实现
  `IUiModule` 的公开类型；不注册任何窗口。
- 验收：Smoke 断言程序集中 `IUiModule` 实现数为 0。

### REQ-002 指令分类与只读性

- 目的：AI 巡检整个项目库时必须保证不会写坏任何工作树。
- 要求：
  1. 全部指令使用 `diana.<类>.<方法>` 三段式，域恒为 `HistoryDiana`
     （归一化后的指令域为 `diana`）。
  2. 类恰有七个：`project`（项目巡检与对齐）、`kit`（小计算）、`relay`（MCP 中继）、
     `docs`（z 说明书）、`worktree`（AI 隔离工作树）、`trial`（候选试用）、
     `release`（候选与正式发布）。
  3. 写命令必须显式列名，当前恰为八条：`diana.relay.call`、`diana.release.cycle`、
     `diana.trial.load/call/unload`、`diana.worktree.root/create/merge`。其余全部声明 `Readonly`。
     `worktree.root` 因同一描述符可写设置，即使省略参数时只查询，仍整体按写命令处理。
     `release.start`、`worktree.remove` 只作内部方法，不登记 MCP。
     `trial.load` 是看一眼候选的 MCP：卸同名正式模块并内存试用，不改发现根、不写正式槽。
  4. 指令由 `IModuleContext.RegisterCommands` 显式登记，不使用反射投影
     ——反射投影会按类型名生成两段式命令（旧 `ToolKit.Sha256` 即如此）。
  5. `diana.docs.catalog` 恒登记；`diana.docs.<域>` 按附着时现场扫描到的 `z-*` 各登记一条。
     通道数量随 z 文件夹增减，Smoke 不断言命令总数。
- 验收：Smoke 断言固定命令、域、七个类、八条写命令、catalog 索引文本与只读性；通道随夹具 z 出现。

### REQ-003 巡检只读且限定在已登记工作树

- 目的：防止路径穿越与对无关目录的扫描。
- 要求：`diana.project.*` 只接受**项目库根下的已登记项目名**，不接受任意路径；
  项目必须是 HistoryClio 独立 Git 仓库（`.git` 目录）或仍带 worktree 指针文件的遗留目录。
  扫描时跳过生成目录（`bin`、`obj`、`.vs`、`node_modules` 等）。
  库根优先 `proj.libraryroot`，其次 `proj.worktreeroot`；指向 HistoryVesta 或含 `HistoryVesta.git` 的路径改写到 `C:\OneHistory\HistoryClio`。不再要求 `proj.barerepo`。
- 验收：Smoke 用临时独立仓验证三条指令可执行且结果结构正确。

### REQ-004 跨项目说明书只从各自 z 经 Diana MCP 消费

- 目的：让任何项目里的 AI 都能取到各模块正式发布的说明书，同时避免在 Diana 再造集中副本。
- 要求：
  1. 消费文档权威编辑源永远在各自仓库的 `b-Office/package/`；发布成功后写入该项目
     `z-*/docs/`，由 `SHA256SUMS` 覆盖。Diana 不保存正文副本。
  2. 跨项目读取必须先执行 `diana.docs.catalog`，把完整索引留在当前对话，再调用一条
     `diana.docs.<域>`。省略 `file` 只列出该通道；带 `file` 才读一篇，且仅限 z 内已登记的
     `.md` / `.txt`、路径不越出 z、不超过 512 KiB、哈希与 SHA256SUMS 一致。
  3. Diana 自身的项目合同放在 `b-Office-Diana/`；仓库不得新增集中模块消费文档区。
- 验收：Smoke 验证 catalog 文本含通道命令、按通道列举与单篇读取、拒绝越出 z 的路径；合同检查验证不存在已退役的集中消费文档目录。

### REQ-006 集中模块发布

- 目的：让各模块保留自己的源码、测试和候选构建逻辑，同时把正式提升和已发布说明书收口到 Diana。
- 要求：
  1. `b-Code/Publish-OneHistoryModule.ps1` 只接受显式登记的项目；普通 `Kind=module` 的登记与验证步骤
     位于 `b-Code/module-publish.manifest.json`，新增普通模块不需要修改主脚本。已登记：
     `HistoryDiana`、`HistoryJanus`、`HistoryMercury`、`HistoryMinerva`（Kind=module）；
     `HistoryVulcan` 是发布器内置的 Kind=host 特例。
  1.1 **两种 Kind 的差异只在快照形状与验证步骤**；普通模块验证步骤由登记表声明，候选构建的调用形状统一为
     `-Configuration Release -OutputRoot <候选目录>`：

     | | module | host |
     | --- | --- | --- |
     | 快照清单 | `module.manifest.json`，身份键 `name` | `manifest.json`，身份键 `product` |
     | 目录结构 | 运行文件平铺，说明书在 `docs/` | `host/` 与 `docs/` 多层 |
     | SHA256SUMS | 带 `/` 的相对路径，递归覆盖 | 带 `/` 的相对路径，递归覆盖 |
     | 源 manifest | 有，需与版本源对齐 | 无（少一处可漂移） |
     | 验证 | 项目合同 + Smoke + UI Smoke | 单元测试 + 质量门禁 + 公共 API 基线 |
  2. 固定顺序为：构建候选 → 校验候选 SHA → 项目合同 → Smoke → UI Smoke →
     把 `b-Office/package/*.md` 写入候选 `docs/` 并重写 SHA256SUMS → 原子提升整个 z。
  3. 默认停在候选；正式提升必须指定 `-Publish`。默认允许脏工作树（先部署后提交）：
     `z-*`（含 `docs/`）是本次发布产物，提交应发生在部署成功之后。
     只有需要「必须从干净 HEAD 复现」时才传 `-RequireCleanSource`。旧开关 `-AllowDirtySource`
     保留给旧调用方，语义等于默认。
  3.1 候选门禁可通过底层 `-SourceWorktree <绝对路径>` 从 AI 工作树运行；正式 `-Publish` 与
      `-SourceWorktree` 互斥，正式 Clio z 只能从项目主树构建。无 `-Publish` 时，工作树必须把已验证
      候选写入**该工作树自己的** `z-*`（宿主扫描根不包含 AI 工作区，这只是候选槽，不是第二套装载器）。
      工作树模式必须把正式 Vulcan 快照根传给构建脚本及全部验证子进程，不能意外链接库内另一份在途宿主源码。
  4. 正式快照提升失败时必须回滚；旧快照保存在各自 `b-Publish\history`。
  5. **只有 HistoryVulcan 宿主**在移动正式目录前，必须按正式 EXE 绝对路径停止前端与后台进程。
     **模块发布不得关闭宿主**：DLL 由宿主从内存流加载，不锁文件。宿主在运行时对模块 z 做原地覆盖
     （不重命名目录，以免拆掉文件监听），然后经 loopback `vulcan.module.reload` 热重载。
     宿主退出后的短暂文件句柄释放须由发布器有限重试处理；若 Windows 仍拒绝目录重命名，
     只能将已验证候选原地同步并立即做完整 manifest/SHA 校验，不得在校验前声明提升成功。
- 验收：已登记项目按登记表可独立运行；HistoryJanus、HistoryMercury、HistoryMinerva（module）与
  HistoryVulcan（host）均已跑通，z 包（含 `docs/`）版本一致且 SHA 可复验。

### REQ-007 Vulcan 发布后修复登录启动

- 目的：Vulcan 正式 Z 路径随版本提升而变化时，后台登录启动项仍指向当前正式宿主。
- 要求：HistoryVulcan 正式提升成功后调用正式快照的 `HistoryVulcan.exe --repair-autostart`；修复失败
  只报告部署后运维警告，不回滚已经验证并提升成功的快照。修复入口必须尊重后台 `svc.autostart`
  设置，显式关闭时不得重新启用。
- 验收：启用时 HKCU Run 的 `HistoryVulcan.Backend` 精确指向当前正式 Z 可执行文件并带
  `--service`；旧 `AppShell.Backend` 被清理，其他启动项不受影响。

### REQ-005 模块身份单一来源

- 目的：manifest 与 `ModuleInfo` 版本不一致会让宿主**静默跳过整个模块**。
- 要求：`ModuleInfo.Version` 从程序集读取，不写字面量；版本源唯一为
  `b-Code-HistoryDiana/HistoryDianaVersion.props`。
- 验收：Smoke 比对 `ModuleInfo` 与程序集版本。

### REQ-008 四项目开发对齐 MCP

- 目的：让 HistoryJanus、HistoryMercury、HistoryMinerva、HistoryVulcan 的 AI 开发会话从同一入口读取项目身份、现行合同和对齐状态。
- 要求：
  1. `diana.project.manifest` 只读取已登记工作树的 `project.manifest.json`。
  2. `diana.project.docs` 只读取 manifest 声明的四类现行文档，不接受任意路径，不超过 512 KiB。
  3. `diana.project.align` 固定检查上述四个项目，报告 manifest 身份、版本和四类文档入口是否存在。
  4. 三条指令全部只读；不得执行任意 Shell，不得写入项目。
- 验收：Smoke 验证命令全集、manifest/document 路径边界和对齐结果结构。

### REQ-009 AI 唯一工作区与隔离分支

- 目的：让 AI 长期只在 Diana 管理的工作区开发，不污染模块源码主线，并保留来源、基线和任务意图。
- 要求：
  1. Janus、Mercury、Minerva、Vulcan 等模块主线只作为源码基线、合并目标和正式发布来源；AI 不得
     把这些主线目录当作日常编辑工作区。`diana.worktree.create` 只接受 HistoryClio 库根下的独立
     Git 项目，创建真实 Git worktree 与
     `ai/<项目>/<短SHA>-<序号>-<agent>-<slug>` 分支；默认根为 `F:\ai工作区`，可由
     `ai.worktreeroot` 或单次 `root=` 覆盖。
  2. 创建后写入不入库的 `Directory.Build.user.props`，把 `HistoryVulcanPackageRoot` 指向来源库的
     正式 `z-HistoryVulcan`；项目没有对应 Import 时明确报告而不伪装成功。
  3. 已有无提交、无改动的闲置工作树时默认拒绝重复创建，显式 `confirm=true` 才允许并行新增。
  4. AI 的源码修改、开发提交和候选门禁全部在 F 盘工作区完成。一轮结束用 `diana.release.cycle`
     在该树提交（门禁 + 写入该树 z + 工作区试用）；若要并回主线，用 `diana.worktree.merge`
     （快进优先，否则普通合并）先卸试用（含前端残留界面）并等到工作区 DLL 解锁，再把分支并入
     main、回收工作区，最后热重载正式 z。git 读写工作区路径使用 UTF-8，避免中文根目录回收失败。
     闲置工作区用 `merge` 回收（与 main 齐时可快进成 already up to date）。回收实现不单独暴露 MCP。
- 验收：Smoke 断言命令注册和只读分级；工作树生命周期以临时 Git 仓集成验证或人工复核验收。

### REQ-010 候选模块调用型试用

- 目的：在不写正式 z、不抢正式命令注册的情况下验证候选模块调用面。
- 要求：
  1. `diana.trial.load path=<目录>` 是看一眼候选的 MCP：校验 `module.manifest.json` 后装入可回收的
     `AssemblyLoadContext`；默认 `ui=true` 时先卸同名正式模块再在前端建验收界面。
     不扫描、不监听、不改发现根、不写 settings、AppData 或正式 z。`path` 是任意含清单的快照目录
     （工作区 `z-*` 或候选目录均可）。`diana.release.cycle` 在提交后仍内部调用同一装载路径。
  2. 候选命令进入私有 `CommandRegistry`，不出现在宿主补全、面板或 MCP 工具表；只能通过
     `diana.trial.call` 调用，`trial.unload` 负责卸载一个或全部候选。
  3. 默认 `ui=true`，一条命令完成卸正式模块、内存试用和前端界面；只验调用面时显式 `ui=false`。
     **界面不在 Diana 所在进程创建**：Diana 住在无窗 `--service` 后台，那里没有 `IShellUiRegistrar`
     也没有 Dispatcher，WPF 对象也不可能递过进程边界。`ui=true` 一律经
     `CommandBus.FrontendExecutor` 中继到宿主 3.11.4 的 `vulcan.module.trialui.load`，
     由前端另装一份候选程序集建界面；`trial.unload` 对应中继 `vulcan.module.trialui.unload`。
     前端未连接时 `ui=true` 直接失败，不做静默降级；中继失败不得阻止本地可回收上下文卸载，
     但必须在结果里点名哪个别名的界面没拆掉。
     若同名正式模块已装载，`ui=true` 在中继建界面之前先执行宿主 3.11.5 的
     `vulcan.module.unload`，释放工具窗口 Id；`trial.unload` 在没有仍占用该位置的试用后
     再 `vulcan.module.reload` 装回正式模块。不得对 HistoryDiana 自己执行卸载。
     宿主缺少 `vulcan.module.unload` 时 `ui=true` 失败并点名 3.11.5，不得继续建界面。
     候选 `Attach` 仍可能产生进程级副作用，必须在手册中明确并要求及时卸载。
  4. 试用程序集从内存流装载，不锁工作区 DLL。Diana 热重载会丢掉静态试用表；宿主 Diana 登记命令、
     `trial.unload` 与 `worktree.merge` 必须 `Unload` 名为 `diana.trial:*` 以及仍映射磁盘文件的
     可回收上下文，再 GC，不得要求关闭宿主。正在试用装载中的 HistoryDiana 副本不得清扫自己。
- 验收：Smoke 断言 load/call/unload 为写命令、list 为只读，且登记 load；集成验证候选命令不进入正式注册表；
  `ui=true` 在无前端中继时失败且不残留试用条目；有前端时同名正式模块先 `vulcan.module.unload`，
  HistoryDiana 自身跳过；缺少 unload 时失败并点名 3.11.5；腾出位置的试用卸完后 `vulcan.module.reload`；
  丢掉试用表后清扫残留 ALC 必须释放候选 DLL。

### REQ-011 MCP 原生模块开发管线

- 目的：让新 AI 仅凭 Diana 文档和 MCP 工具即可发现并执行开发主流程，不必猜脚本路径。
- 要求：
  1. `module.manifest.json` 的 `mcpExposure` 为 `standard`；只读描述符投影为 `readonly`，八条写命令
     投影为 `standard`，Diana 不登记 `dangerous` 或 `hidden` 命令。
  2. `diana.release.cycle` 在分离子进程中跑集中发布脚本并等待结束：主树走 `publish=true` 后提交；
     工作树写入该树 `z-*` 后提交，再内部试用装载（默认 `ui=true`，先卸同名正式模块）。
     `status/log` 只从持久日志与退出码文件判断状态，供超时或自发布热重载后排障，不作为启动入口。
  3. `diana.relay.list/describe/call` 每次连接 loopback MCP，使用当前策略的实时工具目录；
     `relay.call` 不得越过策略调用隐藏工具，超时后不得自动重试可能仍在执行的写操作。
  4. `b-Office-Diana/package/模块开发手册.md` 是开发主入口，顺序固定为：catalog 读正式合同 →
     开工作树 → 改代码 → 看一眼用 `diana.trial.load`（不必 cycle）→
     `diana.release.cycle`（门禁、工作区 z、提交、试用）→ 继续开发或
     `diana.worktree.merge` 并回主线并回收工作区。宿主 HistoryVulcan 走同一套 create/cycle/merge，
     但 cycle 后不 `trial.load`，merge 不把 EXE 热重载进当前进程；正式 EXE 在跑时 merge 失败，
     必须先停进程再并、并完再启动。主树 `publish=true` 仍只从主树发生。
     Diana 不提供 push 或建 PR。
- 验收：Smoke 验证命令类与安全分级；运行时自动生成命令面验证 MCP 工具名、等级和当前策略可见性；
  项目合同检查验证手册入口存在且链接有效。

### 质量属性

| 编号 | 属性 | 可度量要求 | 验收方式 |
| --- | --- | --- | --- |
| QA-001 | 可装载性 | 宿主发现 1 个模块；固定 26 条命令；文档通道数随现场 z 变化 | Smoke |
| QA-002 | MCP 安全 | 八条写命令显式列名，其余全部只读；候选命令不直接进入 MCP | Smoke + 运行时手册 |
| QA-003 | 供应链 | z 快照每个文件都被 SHA256SUMS 覆盖 | 校验脚本 |
| QA-004 | 文档可追溯 | 已发布 Markdown 位于 z/docs，被 SHA256SUMS 覆盖；catalog 现场扫描 | Smoke + 发布后复核 |
| QA-005 | 发布原子性 | 含 docs 的模块 z 一次提升成功，否则恢复旧版本 | 发布脚本故障路径 + 发布后复核 |
| QA-006 | 开发隔离 | 工作树候选不能正式促级；正式发布只从主树发生 | release 参数门禁 + 集成验证 |
| QA-007 | 可发现性 | 新 AI 从 README/manifest 能定位唯一模块开发手册和七类命令边界 | 项目合同检查 + 文档复核 |

## 系统架构

| 组件 | 路径 | 职责 |
| --- | --- | --- |
| 模块入口 | `b-Code-HistoryDiana/ModuleInfo.cs` | 模块身份，版本取自程序集 |
| 命令注册 | `b-Code-HistoryDiana/HistoryDianaCommands.cs` | 唯一注册入口，登记七类指令 |
| 巡检 | 同上 | `diana.project.summary/recent/largest` |
| 小工具 | `b-Code-HistoryDiana/DianaKitCommands.cs` | `diana.kit.sha256/base64/guid/now` |
| 工具中继 | `b-Code-HistoryDiana/DianaRelayCommands.cs` + `OhsmcpClient.cs` | `diana.relay.list/describe/call` |
| z 文档通道 | `b-Code-HistoryDiana/DianaZDocCommands.cs` | `diana.docs.catalog` 与按 z 扩展的 `diana.docs.<域>` |
| AI 工作树 | `b-Code-HistoryDiana/DianaWorktreeCommands.cs` | worktree 根、创建、列举、回收、并回主线及宿主快照覆盖点 |
| 候选试用 | `b-Code-HistoryDiana/DianaTrialCommands.cs` | 私有命令表与可回收内存加载，不进入正式发现和 MCP |
| MCP 发布面 | `b-Code-HistoryDiana/DianaReleaseCommands.cs` | 分离子进程启动管线，cycle 等待提交，持久日志状态与 SourceWorktree 转换 |
