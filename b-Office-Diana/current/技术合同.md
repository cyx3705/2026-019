# HistoryDiana 技术合同

本文件合并当前有效的需求与架构。关键决策单独保存在 `有效决策.md`；已失效内容移入
`../history/`，不得继续作为实现依据。

## 现行需求

### REQ-001 无 UI 模块

- 目的：Diana 服务于 AI，不占用用户的界面空间。
- 要求：`module.manifest.json` 的 `ui` 恒为 `false`；程序集不得包含实现
  已移除 `IUiModule` 的公开类型；不注册任何窗口。
- 验收：Smoke 断言程序集中不存在已移除的 `IUiModule` 类型或 UI 生命周期类型。

### REQ-002 指令分类与只读性

- 目的：AI 巡检整个项目库时必须保证不会写坏任何工作树。
- 要求：
  1. 全部指令使用 `diana.<类>.<方法>` 三段式，宿主按模块名归一化为 `diana` 域。
  2. 类恰有四个：`project`（项目巡检与对齐）、`kit`（小计算）、`relay`（MCP 中继）、
     `docs`（z 说明书）。模块开发闭环（工作区、发布、装机）不在本模块。
  3. 写命令必须显式列名，当前恰为一条：`diana.relay.call`。其余全部声明 `Readonly`。
     不得再登记 `diana.worktree.*`、`diana.release.*`、`diana.trial.*`。
  4. 指令由 `IModuleContext.RegisterCommands` 显式登记，不使用反射投影
     ——反射投影会按类型名生成两段式命令（旧 `ToolKit.Sha256` 即如此）。
  5. `diana.docs.catalog` 恒登记；`diana.docs.<域>` 按附着时现场扫描到的 `z-*` 各登记一条。
     通道数量随 z 文件夹增减，Smoke 不断言运行时总命令数。
- 验收：Smoke 断言固定命令、域、四个类、唯一写命令、catalog 索引文本与只读性；通道随夹具 z 出现。

### REQ-003 巡检只读且限定在已登记工作树

- 目的：防止路径穿越与对无关目录的扫描。
- 要求：`diana.project.*` 只接受**项目库根下的已登记项目名**，不接受任意路径；
  项目必须是 HistoryClio 独立 Git 仓库（`.git` 目录）或仍带 worktree 指针文件的遗留目录。
  扫描时跳过生成目录（`bin`、`obj`、`.vs`、`node_modules` 等）。
     库根由 Diana 运行时解析器读取 `HISTORYCLIO_ROOT`，未设置时使用宿主默认的 `C:\OneHistory\HistoryClio`；不从 `IModuleContext` 读取宿主设置。
- 验收：Smoke 用临时独立仓验证三条指令可执行且结果结构正确。

### REQ-004 跨项目说明书只从各自 z 经 Diana MCP 消费

- 目的：让任何项目里的 AI 都能取到各模块正式发布的说明书，同时避免在 Diana 再造集中副本。
- 要求：
   1. 消费文档权威编辑源永远在各自仓库的 `b-Office/package/`；发布成功后写入该项目
      `z-Publish/HistoryX-vX.Y.Z/docs/`，由 `SHA256SUMS` 覆盖。Diana 不保存正文副本，也不回退旧发布目录。
  2. 跨项目读取必须先执行 `diana.docs.catalog`，把完整索引留在当前对话，再调用一条
     `diana.docs.<域>`。省略 `file` 只列出该通道；带 `file` 才读一篇，且仅限 z 内已登记的
     `.md` / `.txt`、路径不越出 z、不超过 512 KiB、哈希与 SHA256SUMS 一致。
     `file` 可以是 catalog 相对路径，也可以是通道内唯一的文件名。
     超过 12 KiB 的正文必须带 `heading=`，否则只返回章节目录，避免整篇灌进对话。
     `heading=` 可以是 Markdown 标题，也可以是 `x.y.z` 版本号（切出该版本的列表项，直到下一条不同版本）。
      长文目录同时列出章节和版本号。当前 Vulcan 5.1.2 消费变更摘要应 `heading=5.1.2`，不要用会吞掉全部历史的
      `heading=主要变化`。
  3. Diana 自身的项目合同放在 `b-Office-Diana/`；仓库不得新增集中模块消费文档区。
- 验收：Smoke 验证 catalog 文本含通道命令、按通道列举与单篇读取、拒绝越出 z 的路径；合同检查验证不存在已退役的集中消费文档目录。

### REQ-006 集中模块发布

- 目的：让各模块保留自己的源码、测试和候选构建逻辑，同时把正式提升和已发布说明书收口到 Diana。
- 要求：
  1. 宿主模块开发管线只接受显式登记的项目；普通 `Kind=module` 的登记与验证步骤
     位于宿主 `eng/pipeline/module-publish.manifest.json`，新增普通模块不需要修改主脚本。已登记：
     `HistoryDiana`、`HistoryJanus`、`HistoryMercury`、`HistoryMinerva`（Kind=module）；
     `HistoryVulcan` 是发布器内置的 Kind=host 特例。
  1.1 **两种 Kind 的差异只在快照形状与验证步骤**；普通模块验证步骤由登记表声明，候选构建的调用形状统一为
     `-Configuration Release -OutputRoot <候选目录>`：

      | | module | host |
      | --- | --- | --- |
      | 快照清单 | `module.manifest.json`，身份键 `name` | `manifest.json`，身份键 `product` |
       | 当前候选根 | `z-Publish/HistoryX-vX.Y.Z/` | `z-Publish/host/`（Vulcan 5.1.2） |
      | 目录结构 | 运行文件平铺，说明书在 `docs/` | 当前根含 `host/`、`docs/`、`manifest.json`、`SHA256SUMS`；旧版本只在 `history/` |
      | SHA256SUMS | 带 `/` 的相对路径，递归覆盖 | 带 `/` 的相对路径，递归覆盖 |
      | 源 manifest | 有，需与版本源对齐 | 无（少一处可漂移） |
      | 验证 | 项目合同 + Smoke + UI Smoke | 单元测试 + 质量门禁 + 公共 API 基线（版本升且 Unshipped 未变时，发布器先继承上一版基线目录；API 真变了则失败，不得自动批准） |
    1.2 `HistoryAurora` 是与宿主并列的独立应用，不属于当前模块登记表。其现有构建脚本不接受统一的
       `-OutputRoot`，且应用/模块契约仍处于过渡状态；在入口、快照形状和门禁对齐前，发布器不得添加
       Aurora 适配器或登记项。升级协调顺序为先刷新 Vulcan 5.1.2 宿主，再运行 Aurora 自己的门禁。
    2. 固定顺序为：构建候选 → 校验候选 SHA → 项目合同 → Smoke → UI Smoke →
       把 `b-Office/package/*.md` 写入模块候选的 `docs/` 或宿主当前根的 `docs/`，重写 SHA256SUMS →
       原子提升正式运行快照。
   3. 默认停在候选；正式提升必须指定 `-Publish`。默认允许脏工作树（先部署后提交）：普通模块的
      `z-Publish/HistoryX-vX.Y.Z`（含 `docs/`）是本次发布产物；Vulcan 宿主的当前产物是平铺的
      `z-Publish/host/`（根部含 `manifest.json`、`SHA256SUMS`、`docs/`）。提交应发生在部署成功之后。
     只有需要「必须从干净 HEAD 复现」时才传 `-RequireCleanSource`。旧开关 `-AllowDirtySource`
     保留给旧调用方，语义等于默认。
  3.1 候选门禁可通过底层 `-SourceWorktree <绝对路径>` 从 AI 工作树运行；正式 `-Publish` 与
      `-SourceWorktree` 互斥，正式 Clio z 只能从项目主树构建。无 `-Publish` 时，工作树必须把已验证
      候选写入**该工作树自己的** `z-Publish/HistoryX-vX.Y.Z`，随后调用 `vulcan.module.install` 热重载运行槽。
      工作树模式必须把正式 Vulcan 快照根传给构建脚本及全部验证子进程，不能意外链接库内另一份在途宿主源码。
  4. 正式快照提升失败时必须回滚；普通模块旧快照保存在各自 `z-Publish\history`，Vulcan 宿主旧的平铺
     payload 也只能作为不可变副本归档到 `z-Publish\history`，不得留在当前根冒充候选。
  5. **只有 HistoryVulcan 宿主**在移动正式目录前，必须按正式 EXE 绝对路径停止前端与后台进程。
     **模块发布不得关闭宿主**：DLL 由宿主从内存流加载，不锁文件。宿主在运行时对模块 z 做原地覆盖
     （不重命名目录，以免拆掉文件监听），然后经 loopback `vulcan.module.reload` 热重载。
     宿主退出后的短暂文件句柄释放须由发布器有限重试处理；若 Windows 仍拒绝目录重命名，
     只能将已验证候选原地同步并立即做完整 manifest/SHA 校验，不得在校验前声明提升成功。
 - 验收：已登记项目按登记表可独立运行；HistoryJanus、HistoryMercury、HistoryMinerva（module）与
   HistoryVulcan（host）均已跑通，普通模块版本化 z 包和 Vulcan 平铺宿主根（均含 `docs/`）版本一致且
   SHA 可复验；HistoryAurora 在契约对齐前明确标为未登记，不得以“已通过模块管线”交付。

### REQ-007 Vulcan 发布后修复登录启动

- 目的：Vulcan 正式 Z 路径随版本提升而变化时，后台登录启动项仍指向当前正式宿主。
- 要求：HistoryVulcan 正式提升成功后调用正式快照的 `HistoryVulcan.exe --repair-autostart`；修复失败
  只报告部署后运维警告，不回滚已经验证并提升成功的快照。修复入口必须尊重后台 `svc.autostart`
  设置，显式关闭时不得重新启用。
- 验收：启用时 HKCU Run 的 `HistoryVulcan.Backend` 精确指向当前正式 Z 可执行文件并带
  `--service`；旧 `AppShell.Backend` 被清理，其他启动项不受影响。

### REQ-005 模块身份单一来源

- 目的：manifest 与 `ModuleInfo` 版本不一致会让宿主**静默跳过整个模块**。
- 要求：`ModuleInfo.Version` 从程序集读取，不写字面量；版本源唯一为
  `b-Code-HistoryDiana/HistoryDianaVersion.props`。
- 验收：Smoke 比对 `ModuleInfo` 与程序集版本。

### REQ-008 四项目开发对齐 MCP

- 目的：让 HistoryJanus、HistoryMercury、HistoryMinerva、HistoryVulcan 的 AI 开发会话从同一入口读取项目身份、现行合同和对齐状态。
- 要求：
  1. `diana.project.manifest` 只读取已登记工作树的 `project.manifest.json`。
  2. `diana.project.docs` 只读取 manifest 声明的四类现行文档，不接受任意路径，不超过 512 KiB。
  3. `diana.project.align` 固定检查上述四个项目，报告 manifest 身份、版本和四类文档入口是否存在。
  4. 三条指令全部只读；不得执行任意 Shell，不得写入项目。
- 验收：Smoke 验证命令全集、manifest/document 路径边界和对齐结果结构。

### REQ-009 AI 唯一工作区与隔离分支

- 目的：让 AI 长期只在隔离工作区开发，不污染模块源码主线。
- 要求：工作区生命周期由宿主 `vulcan.dev.start/submit/finish` 拥有，不在 Diana 命令面。
  Diana 只提供巡检、文档通道和中继。默认根仍为 `F:\ai工作区`。
- 验收：运行时 `diana` 域不含 `worktree` 类；宿主登记 `vulcan.dev.*`。

### REQ-010 候选与历史包严格重载

- 目的：候选测试和回退使用与正式模块相同的唯一运行槽。
- 要求：装机走宿主 `vulcan.module.install`；Diana 不再转发 `trial.load`。
  发布脚本只负责构建、门禁和写入版本化候选。
- 验收：Smoke 断言不登记 `diana.trial.*`。

### REQ-011 MCP 原生模块开发管线

- 目的：新 AI 凭宿主 MCP 即可走开发主流程，不必猜脚本路径。
- 要求：
  1. `module.manifest.json` 的 `mcpExposure` 为 `standard`；只读描述符投影为 `readonly`，
     `diana.relay.call` 投影为 `standard`。
  2. 开发闭环为 `vulcan.dev.start` → `vulcan.dev.submit` → `vulcan.dev.finish`。
     手册入口在 HistoryVulcan `b-Office/package/模块开发手册.md`。
  3. `diana.relay.list/describe/call` 连接当前宿主 loopback MCP 的实时工具目录。
- 验收：Smoke 验证四类命令与唯一写命令；项目合同不再要求 Diana 包内模块开发手册。

### 质量属性

| 编号 | 属性 | 可度量要求 | 验收方式 |
| --- | --- | --- | --- |
| QA-001 | 可装载性 | 宿主发现 1 个模块；固定四类命令；文档通道数随现场 z 变化 | Smoke |
| QA-002 | MCP 安全 | 唯一写命令 `relay.call`，其余全部只读 | Smoke + 运行时手册 |
| QA-003 | 供应链 | z 快照每个文件都被 SHA256SUMS 覆盖 | 校验脚本 |
| QA-004 | 文档可追溯 | 已发布 Markdown 位于 z/docs，被 SHA256SUMS 覆盖；catalog 现场扫描 | Smoke + 发布后复核 |
| QA-005 | 发布原子性 | 含 docs 的模块 z 一次提升成功，否则恢复旧版本 | 发布脚本故障路径 + 发布后复核 |
| QA-006 | 开发隔离 | 工作树候选不能正式促级；正式发布只从主树发生 | release 参数门禁 + 集成验证 |
| QA-007 | 可发现性 | 新 AI 从 README/manifest 能定位四类命令，开发闭环指向宿主 | 项目合同检查 + 文档复核 |

## 系统架构

| 组件 | 路径 | 职责 |
| --- | --- | --- |
| 模块入口 | `b-Code-HistoryDiana/ModuleInfo.cs` | 模块身份，版本取自程序集 |
| 命令注册 | `b-Code-HistoryDiana/HistoryDianaCommands.cs` | 唯一注册入口，登记四类指令 |
| 巡检 | 同上 | `diana.project.summary/recent/largest` |
| 小工具 | `b-Code-HistoryDiana/DianaKitCommands.cs` | `diana.kit.sha256/base64/guid/now` |
| 工具中继 | `b-Code-HistoryDiana/DianaRelayCommands.cs` + `OhsmcpClient.cs` | `diana.relay.list/describe/call` |
| z 文档通道 | `b-Code-HistoryDiana/DianaZDocCommands.cs` | `diana.docs.catalog` 与按 z 扩展的 `diana.docs.<域>` |
| 宿主运行时输入 | `b-Code-HistoryDiana/DianaRuntime.cs` | `HISTORYCLIO_ROOT` 与 Vulcan `endpoint.json`，不读取 `IModuleContext` 设置 |
| 验证 | `b-Code-HistoryDiana/tests/HistoryDiana.Smoke` | 身份、固定命令、通道夹具、只读性、无 UI |
| 模块开发管线 | HistoryVulcan `HistoryVulcan.Cli.exe --cli vulcan.dev.*` | 由用户审查后授权 submit/finish |
| 发布区 | 普通模块 `z-Publish/HistoryX-vX.Y.Z/`；Vulcan 宿主 `z-Publish/host/` | 当前候选；宿主只装载其复制到 AppData 的运行副本 |

### 不变量

- 唯一版本源：`b-Code-HistoryDiana/HistoryDianaVersion.props`，当前源码版本 `2.2.0`。
- 目标运行宿主：HistoryVulcan `5.1.2` 起（开发路线在宿主）；当前宿主候选固定为平铺 `z-Publish/host/`。
- 可重建生成物：`bin/`、`obj/`、`z-Publish/`。
- 当前候选：`z-Publish/HistoryDiana-v2.2.0/`；历史包直属位于 `z-Publish/history/HistoryDiana-vX.Y.Z/`。
