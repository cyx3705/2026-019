# HistoryDiana 原生控制台日志查看需求书

状态：已实现，候选验证中
目标版本：HistoryDiana 2.4.0 / HistoryAurora 1.14.0
依赖方：HistoryAurora / HistoryVulcan 当前进程命令总线

## 一、问题与目标

AI 排查 HistoryVulcan 前端故障时，控制台往往已经显示了准确的异常、来源和时间。现有 Diana
只能截图前端或由 AI 扫描磁盘 `shell-*.log`：截图不适合提取长堆栈，磁盘日志又不等于 Aurora
控制台当前缓冲区，还会混入其他进程、历史实例和大量无关内容。

本需求增加只读命令 `diana.log.read`，让 AI 直接查询**当前 HistoryVulcan 前端实例中 Aurora
控制台正在使用的内存日志缓冲区**，取得结构化日志记录。该能力用于诊断，不控制界面，不改变
控制台筛选器，不产生截图，也不扫描磁盘日志。

典型调用：

```text
diana.log.read minlevel=error source=shell.chrome limit=100
```

对于页面拖出故障，AI 应先调用该命令读取异常，再决定是否需要图形捕获或真实鼠标复现。

## 二、范围与边界

### 范围内

- 读取当前前端实例的 Aurora 控制台内存缓冲区。
- 按最低级别、来源、关键字和时间过滤，限制返回条数。
- 返回稳定顺序、单调序号和实例身份，支持增量读取。
- 保留多行异常和堆栈，不把一条异常拆成多条无上下文文本。
- 通过 Diana 的 MCP 只读工具直接调用。

### 范围外

- 不读取或跟随 `%AppData%` 下的 `shell-*.log`，不把文件尾读伪装成控制台读取。
- 不使用 `diana.view.capture`、OCR、UI Automation、WPF 视觉树或窗口激活。
- 不清空日志，不修改 Aurora 的级别、来源、关键字、自动滚动或静音设置。
- 不订阅无限流，不在后台轮询；每次调用只取得一个有界快照。
- 不读取其他应用、其他用户会话、已退出宿主或上一次宿主实例的日志。
- 不通过 `diana.relay.call`、HTTP 回环或 MCP 再入来实现模块间调用。

## 三、运行边界

```text
AI / MCP
   -> diana.log.read（公开、Readonly）
      -> IModuleContext.Bus（当前进程内调用）
         -> Aurora 控制台快照提供者（只读、无 UI 副作用）
            -> 当前控制台内存缓冲区
```

Aurora 拥有控制台缓冲区，Diana 不得引用 Aurora 程序集、反射私有字段或复制一份旁路缓冲区。
实施时由 Aurora 或宿主登记当前进程内的只读快照提供者；建议命令名为
`aurora.log.snapshot`。Diana 只通过现有 `IModuleContext.Bus` 调用它，并把结果整理为稳定的
AI 查询合同。

提供者缺失、前端未附着、实例正在热重载或响应结构不受支持时，`diana.log.read` 必须明确失败，
说明当前不可读取；不得静默回退截图或磁盘文件。

## 四、功能需求

### REQ-013 原生读取当前控制台日志

1. Diana 新增 `log` 类和只读命令 `diana.log.read`。命令不得写文件、改变 UI 或产生外部请求。
2. 数据源必须是当前 Aurora 控制台实际使用的内存记录集合；返回内容与控制台可显示记录同源，
   但不受当前 UI 筛选器、选中行、滚动位置或窗口可见性的影响。
3. 命令参数如下：

| 参数 | 默认值 | 要求 |
| --- | --- | --- |
| `minlevel` | `error` | `trace/debug/info/warn/error/fatal`，大小写不敏感 |
| `source` | 空 | 规范化来源的大小写不敏感精确匹配 |
| `keyword` | 空 | 对来源和完整消息做大小写不敏感包含匹配 |
| `since` | 空 | ISO 8601 时间；只返回该时刻及之后的记录 |
| `after` | 空 | 上次结果的单调序号；只返回更晚记录，用于增量查询 |
| `limit` | `100` | 范围 `1..500`；任何调用都不得无界返回 |

4. 默认按序号倒序返回最近记录；提供 `after` 时按序号正序返回，便于 AI 继续读取新增日志。
5. 每条记录至少包含 `sequence`、`timestamp`、`level`、`source` 和 `message`。`message` 保留原始换行；
   若生产端有结构化异常，可额外返回 `exceptionType` 和 `exception`，但不得从文本猜测类型。
6. 快照结果至少包含 `frontendInstanceId`、`capturedAt`、`oldestSequence`、`newestSequence`、
   `matchedCount`、`returnedCount`、`truncated`、`nextAfter` 和 `entries`。
7. `sequence` 在单个前端实例内严格递增。热重载不得把旧提供者对象留在 Diana；前端实例变化时
   `frontendInstanceId` 必须变化，调用方不得跨实例复用 `after`。
8. 单次结构化结果上限为 256 KiB。超过上限时按完整记录边界截断并置 `truncated=true`；
   不得在没有标记的情况下截断消息或堆栈。
9. 空缓冲区或筛选无匹配时返回成功和空 `entries`。非法级别、时间、序号或数量返回可修正的参数错误。
10. 命令只读取已进入 Aurora 控制台正常净化链的记录，不绕过既有敏感值清理；不得读取原始日志接收器、
    环境变量、命令参数对象或其他未展示给控制台的数据。

## 五、返回示例

```json
{
  "frontendInstanceId": "c6605a56a1f64d65a56b24a71600e389",
  "capturedAt": "2026-08-31T18:20:00+08:00",
  "oldestSequence": 4102,
  "newestSequence": 4277,
  "matchedCount": 1,
  "returnedCount": 1,
  "truncated": false,
  "nextAfter": 4277,
  "entries": [
    {
      "sequence": 4277,
      "timestamp": "2026-08-31T18:19:42.183+08:00",
      "level": "Error",
      "source": "shell.chrome",
      "message": "页面拖出失败\nSystem.InvalidOperationException: ..."
    }

```

示例只定义形状，不是现场错误证据。

## 六、质量要求

- 查询当前 10,000 条以内的有界缓冲区时，P95 应在 100 ms 内完成；筛选在生产端执行，Diana
  不先拉取全部记录再截断。
- 快照必须线程安全；读取期间新增日志不能导致枚举异常、重复序号或顺序漂移。
- 查询自身产生的命令审计日志不得递归污染本次快照；结果边界以提供者开始取快照的时刻为准。
- 前端最小化、隐藏或被其他窗口遮挡时仍可读取；该能力不依赖像素和窗口句柄。
- Aurora 未装载时只影响本命令，不影响 Diana 其他五类命令。

## 七、验证合同

### VERIFY-DIANA-CONSOLE-LOG

1. Smoke 使用内存提供者覆盖级别、来源、关键字、`since`、`after`、默认顺序和 `limit` 边界。
2. 覆盖多行异常、空缓冲区、超出 256 KiB、非法参数、提供者缺失、结构版本未知和实例切换。
3. 断言 `diana.log.read` 为 `Readonly=true`，新增后命令类集合从五类变为六类，写命令仍只有
   `diana.relay.call` 与 `diana.view.capture`。
4. 断言实现不枚举 `shell-*.log`、不调用截图代码、不创建文件、不访问网络、不引用 Aurora 程序集。
5. 用可替换提供者执行热重载测试，确认 Diana 每次从当前总线解析提供者，不持有已卸载实例。
6. 真实宿主验收先写入带唯一标记的 Info、Warn、Error 和多行异常，再通过 MCP 调用
   `diana.log.read keyword=<标记>`；返回的级别、来源、消息、顺序和实例 ID 必须与 Aurora
   当前控制台缓冲区一致。
7. 页面拖出故障验收中，先记录 `nextAfter`，执行一次真实拖出，再以
   `diana.log.read after=<序号> minlevel=error` 查询；若控制台出现异常，Diana 必须返回同一条完整异常，
   无需截图或扫磁盘日志。
8. 对新增测试做失败正对照，并运行 Diana Release 构建、Smoke、项目合同、格式检查和公开命令门禁。

## 八、交付与兼容

- Diana 2.4.0 新增公开只读命令，版本源、manifest、README、技术合同、验证合同与 Smoke 同步。
- Aurora 1.14.0 提供隐藏只读 `aurora.log.snapshot`；Diana 不引用 Aurora 程序集。
- 不删除或改变现有命令。现有 `diana.view.*` 保留用于视觉问题；日志问题默认先用
  `diana.log.read`。
- Aurora/宿主提供者是实施依赖，必须与 Diana 候选在同一轮真实宿主验收中核对；任一侧未就绪时
  不得把文件读取或截图回退声明为通过。
