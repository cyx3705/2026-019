# HistoryDiana 验证合同

## 验证层级

| 层级 | 范围 | 命令 |
| --- | --- | --- |
| 项目合同 | manifest、活动目录、必需文档、Markdown 链接和实例化状态 | `powershell -NoProfile -ExecutionPolicy Bypass -File .\b-Code\Test-ProjectContract.ps1 -Instantiation` |
| 构建 | Diana 模块与测试项目 Release 编译 | `dotnet build .\b-Code-HistoryDiana\HistoryDiana.csproj -c Release` |
| Smoke | 模块身份、五类命令、MCP 安全分级、无自有 UI、PNG 编解码、巡检与 z 文档边界 | `dotnet run --project .\b-Code-HistoryDiana\tests\HistoryDiana.Smoke\HistoryDiana.Smoke.csproj -c Release` |
| 快照校验 | 普通模块 `z-Publish/HistoryX-vX.Y.Z`，以及 Vulcan 5.1.2 的平铺 `z-Publish/host` manifest、运行文件、docs 与递归 SHA-256 | 逐行读取对应 `SHA256SUMS` 并复算 |
| 候选管线 | 在 Diana 模块工作树构建、合同检查和 Smoke，不正式提升 | `HistoryVulcan.Cli.exe --cli vulcan.dev.submit`（待授权） |
| 工作树候选 | 指定 AI 开发工作区运行模块门禁，写入该树 `z-*`，禁止正式 Clio 提升 | `vulcan.dev.submit ... worktree=<路径>`（待授权） |
| 正式发布 | 审查后由模块管线提交、安装并热重载 | `vulcan.dev.finish`（待授权） |
| MCP 运行面 | 工具名、readonly/standard 等级、当前策略可见性 | `diana.relay.list` / `diana.relay.describe`，或宿主运行时查询 |

先运行项目合同、构建和 Smoke。候选/正式管线会写 `z-Publish` 或正式 z，只在任务明确需要时运行；
正式发布、提交和推送均不由普通验证隐式授权。

2026-08-31 当前：Diana `2.3.0` 与 Vulcan `>= 5.1.2`。正式 catalog 已提供 Diana 2.3.0；
`diana.worktree/release/trial` 已从命令面删除，`IModuleContext.Settings` 也已移除。Diana 定位为 AI 工具区；
唯一基础设施例外是宿主冻结且仅 CLI 可用的 `vulcan.dev.start/submit/finish`。

## Smoke 必须覆盖

1. 程序集恰好提供 1 个 `HistoryDiana` 模块入口；`ModuleInfo.Version` 与程序集版本一致。
2. 所有命令使用 `diana.<类>.<方法>`，域为 `HistoryDiana`；类恰为
   `docs / kit / project / relay / view` 五个。
3. 固定命令面包含 `diana.docs.catalog` 和 `diana.docs.read`；新增 z 模块不增加命令数，`read domain=` 每次实时解析。
4. 写命令必须显式列名：仅 `relay.call` 与 `view.capture`；除此以外全部 `Readonly=true`。不得再登记
   `diana.worktree.*`、`diana.release.*`、`diana.trial.*`。
5. project 基础巡检只接受库根下独立 Git 项目并返回结构化结果；manifest 缺失或路径越界明确失败；
   默认排除 `z-Publish` / `artifacts`，`includeGenerated=true` 时重新纳入。
6. `diana.docs.catalog` 输出必须包含 `diana.docs.read domain=<域>`；read 省略 file 只列举，带 file 才读取；
   越出 z、经过重解析点、未被 SHA256SUMS 覆盖或超限的文件必须失败；损坏、身份版本与目录不一致或
   未受 SHA256SUMS 保护的 manifest 不得形成通道。唯一文件名可解析到 catalog 路径；
   `heading=` 只返回该节或该版本条目；超过 12 KiB 且未带 heading 时只返回章节和版本目录。
   文档正文按大小和 heading 规则截断；heading 不存在时建议最多 20 项并指向完整目录。
7. 程序集不含 `IUiModule` 类型或遗留 `ProjectPulse` 类型。
8. 新增类或写命令时，Smoke 的类集合和写命令白名单必须与技术合同同一次更新。
9. 不得登记 `diana.trial.load`；装机由宿主 `vulcan.module.install` 承担。
10. 候选测试不产生第二份程序集或私有注册表；测试不通过时不自动恢复，由用户再次选择主候选或历史包。
11. 宿主不是模块：`vulcan.module.list` 列出已装载模块；HistoryVulcan 自身仍是宿主，不进入模块包。
12. Vulcan 5.1.2 当前宿主候选必须是平铺 `z-Publish/host/`，根部存在 `manifest.json`（`product=HistoryVulcan`）、
    `SHA256SUMS`、`docs/` 和 `host/HistoryVulcan.exe`；不得从直属 `HistoryVulcan-vX.Y.Z` 目录选取当前依赖，旧包只能在
    `z-Publish/history/` 归档。
13. HistoryAurora、HistoryPortunus 已在宿主 `module-publish.manifest.json` 登记为 `kind=module`。
    不得再以“不接受 `-OutputRoot`”或“Diana 模块登记表”描述它们；模块发布只走宿主开发管线。
14. `diana.view.windows` 只能返回 HistoryVulcan 窗口；合成像素必须能编码并重新解码为尺寸一致的 PNG。
    真实前端验收还须复算 `view.capture` 返回的 SHA-256、核对尺寸与 `NonUniform=true`，并实际打开 PNG。
15. MCP 中继默认从 Cursor `mcp.json` 读取无令牌的本机 `/mcp` URL，拒绝非回环地址；
    `Source=module` 的当前 `CommandName` 必须能派生出 MCP 工具名，旧 `McpToolName` 仍作兼容。
16. 可预期的参数、路径、IO、JSON、MCP 与窗口状态错误必须返回具体原因；Smoke 至少断言非法项目名和
    非法窗口句柄，不得只得到 `ArgumentException` / `InvalidOperationException` 类型名。
17. 项目/模块 manifest、运行时模块描述、README、AI 工作合同、四份现行合同、文档中心和复用说明必须
    统一使用“AI 工具区”；关键入口同时明确业务领域能力仍归对应模块，`vulcan.dev.start/submit/finish`
    是唯一基础设施例外且只走 Console CLI。项目合同必须自动拒绝旧定位回流。

Smoke 摘要中的命令数与类数取实际注册结果，不写字面量。版本期望可以读取唯一版本源；若测试仍使用
版本字面量，则版本提升必须与 props、源 manifest、正式 manifest 和测试同一次修改。

## 冻结模块开发管线验收

| 阶段 | 必须成立 | 验收证据 |
| --- | --- | --- |
| 查合同 | 先执行 `diana.docs.catalog`，再读取 catalog 给出的 Vulcan 通道 | catalog 完整输出留在对话中 |
| 开工作树 | 分支与目录含基线 SHA、序号、agent、slug | `vulcan.dev.start` + 工作树 `git status` |
| 候选门禁 | `vulcan.dev.submit` 的 `worktree=` 写入该树 z | submit 日志 + 成功退出码（待授权） |
| 热重载 | `vulcan.dev.submit` 只安装并重载目标模块 | Vulcan 热重载结果 + 运行区 revision |
| 继续或合并 | 审查后 `vulcan.dev.finish` | 主树包含该分支，工作区已删除（待授权） |

当前 Smoke 主要覆盖注册、安全分级、巡检和文档通道。真实 Git worktree 生命周期、候选程序集装卸、
分离发布子进程和正式回滚属于跨进程集成行为；没有运行相应集成步骤时，交付必须明确写“未运行”，
不能用命令已注册代替端到端通过。

## 快照与 MCP 校验

`z-Publish/HistoryDiana-v2.3.0` 至少含 `HistoryDiana.dll`、`HistoryDiana.xml`、`module.manifest.json`、
`SHA256SUMS` 和 `docs/`。manifest 的 `name/version/ui/mcpExposure` 必须分别为
`HistoryDiana`、唯一版本源的值、`false`、`standard`。SHA256SUMS 递归覆盖除自身外的每个正式文件。

当前 standard 策略的运行时手册应显示固定 Diana 命令，文档域由 `diana.docs.read` 的参数动态解析；
standard 写命令是 `diana.relay.call` 与 `diana.view.capture`。旧 worktree/release/trial 命令不得出现在工具表。
