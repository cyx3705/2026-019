# HistoryDiana 验证合同

## 验证层级

| 层级 | 范围 | 命令 |
| --- | --- | --- |
| 项目合同 | manifest、活动目录、必需文档、Markdown 链接和实例化状态 | `powershell -NoProfile -ExecutionPolicy Bypass -File .\b-Code\Test-ProjectContract.ps1 -Instantiation` |
| 构建 | Diana 模块与测试项目 Release 编译 | `dotnet build .\b-Code-HistoryDiana\HistoryDiana.csproj -c Release` |
| Smoke | 模块身份、七类命令、MCP 安全分级、无 UI、巡检与 z 文档边界 | `dotnet run --project .\b-Code-HistoryDiana\tests\HistoryDiana.Smoke\HistoryDiana.Smoke.csproj -c Release` |
| 快照校验 | `z-HistoryDiana` manifest、运行文件与递归 SHA-256 | 逐行读取 `z-HistoryDiana\SHA256SUMS` 并复算 |
| 候选管线 | 从主树构建 Diana 候选并执行登记验证，不正式提升 | `powershell -NoProfile -ExecutionPolicy Bypass -File .\b-Code\Publish-OneHistoryModule.ps1 -Module HistoryDiana` |
| 工作树候选 | 指定 AI 工作树运行同一候选门禁，写入该树 `z-*`，禁止正式 Clio 提升 | 上述命令加 `-SourceWorktree <绝对路径>`；MCP 入口为 `diana.release.cycle name=… worktree=<路径>` |
| 正式发布 | 从主树构建、验证、写 docs、原子提升 z 并热重载 | 候选命令加 `-Publish`；MCP 入口为 `diana.release.cycle name=…`（主树，无 worktree） |
| MCP 运行面 | 工具名、readonly/standard 等级、当前策略可见性 | `diana.relay.list` / `diana.relay.describe`，或宿主运行时查询 |

先运行项目合同、构建和 Smoke。候选/正式管线会写 `b-Publish` 或正式 z，只在任务明确需要时运行；
正式发布、提交和推送均不由普通验证隐式授权。

## Smoke 必须覆盖

1. 程序集恰好提供 1 个 `HistoryDiana` 模块入口；`ModuleInfo.Version` 与程序集版本一致。
2. 所有命令使用 `diana.<类>.<方法>`，域为 `HistoryDiana`；类恰为
   `docs / kit / project / relay / release / trial / worktree` 七个。
3. 固定命令面为 26 条；`diana.docs.<域>` 随夹具 z 动态增加，因此不得断言运行时总命令数。
4. 八条写命令必须显式列名：`relay.call`、`release.cycle`、`trial.load/call/unload`、
   `worktree.root/create/merge`；除此以外全部 `Readonly=true`。不得再登记
   `release.start`、`worktree.remove`。`trial.load` 必须登记，且 `ui` 默认 `true`。
5. project 基础巡检只接受库根下独立 Git 项目并返回结构化结果；manifest 缺失或路径越界明确失败。
6. `diana.docs.catalog` 输出必须包含通道命令名；通道省略 file 只列举，带 file 才读取；
   越出 z、未被 SHA256SUMS 覆盖或超限的文件必须失败。唯一文件名可解析到 catalog 路径；
   `heading=` 只返回该节或该版本条目；超过 12 KiB 且未带 heading 时只返回章节和版本目录。
7. 程序集不含 `IUiModule` 实现，不含遗留 `ProjectPulse` 类型。
8. 新增类或写命令时，Smoke 的类集合和写命令白名单必须与技术合同同一次更新。
9. `ui=true`：无前端中继时失败且不残留试用条目。有前端时，同名正式模块先经
   `vulcan.module.unload` 卸掉再中继 `trialui.load`；候选名为 HistoryDiana 时跳过卸载；
   宿主没有 unload 时失败并点名 3.11.5。腾出位置的试用卸完后执行 `vulcan.module.reload`。
10. 回收工作区：试用表已空时仍须中继 `vulcan.module.trialui.unload`，避免前端占用工作区 DLL。
11. 残留试用 ALC：丢掉静态试用表后，名为 `diana.trial:*` 的可回收上下文仍应占着 DLL；
    宿主清扫后必须能以 `FileShare.None` 打开候选 DLL。试用装载 HistoryDiana 自己时不得把
    正在附着的上下文清掉。
12. 宿主不是模块：`trial.load` 名为 HistoryVulcan 的快照必须失败；`release.modules` 列出
    HistoryVulcan（kind=host）；工作区 cycle 对宿主跳过试用。

Smoke 摘要中的命令数与类数取实际注册结果，不写字面量。版本期望可以读取唯一版本源；若测试仍使用
版本字面量，则版本提升必须与 props、源 manifest、正式 manifest 和测试同一次修改。

## AI 模块开发流程验收

| 阶段 | 必须成立 | 验收证据 |
| --- | --- | --- |
| 查合同 | 先执行 `diana.docs.catalog`，再读取 catalog 给出的 Vulcan 通道 | catalog 完整输出留在对话中 |
| 开工作树 | 分支与目录含基线 SHA、序号、agent、slug；生成的宿主覆盖点不入库 | `diana.worktree.list` + 工作树 `git status` |
| 候选门禁 | `cycle` 的 `worktree=` 转为绝对 SourceWorktree，写入该树 z，所有子进程使用正式 Vulcan 快照根 | release 日志 + 成功退出码 |
| 调用试用 | 未提交看一眼用 `trial.load`（默认 `ui=true`）；`cycle` 之后亦可 `trial.list/call` | `trial.list` / 试用界面 |
| 继续或合并 | 继续在工作区开发并再 `cycle`；或 `worktree.merge` 先卸试用（含前端）再并回、回收、热重载 | 主树包含该分支，工作区已删除 |

当前 Smoke 主要覆盖注册、安全分级、巡检和文档通道。真实 Git worktree 生命周期、候选程序集装卸、
分离发布子进程和正式回滚属于跨进程集成行为；没有运行相应集成步骤时，交付必须明确写“未运行”，
不能用命令已注册代替端到端通过。

## 快照与 MCP 校验

`z-HistoryDiana` 至少含 `HistoryDiana.dll`、`HistoryDiana.xml`、`module.manifest.json`、
`SHA256SUMS` 和 `docs/`。manifest 的 `name/version/ui/mcpExposure` 必须分别为
`HistoryDiana`、唯一版本源的值、`false`、`standard`。SHA256SUMS 递归覆盖除自身外的每个正式文件。

当前 standard 策略的运行时手册应显示：26 条固定 Diana 命令，加现场动态文档通道；当前现场为
31 条（23 readonly、8 standard）。动态 z 数量变化后总数可变，但八条 standard 命令集合不应漂移。
点号命令投影为下划线 MCP 工具名。候选私有命令不得直接出现在工具表。
