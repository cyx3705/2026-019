# HistoryDiana 验证合同

## 验证层级

| 层级 | 范围 | 命令 |
| --- | --- | --- |
| 构建 | 模块与测试项目编译无警告 | `dotnet build .\b-Code-HistoryDiana\HistoryDiana.csproj -c Release` |
| Smoke | 模块身份、命令全集、只读性、无 UI、巡检可执行 | `dotnet run --project .\b-Code-HistoryDiana\tests\HistoryDiana.Smoke\HistoryDiana.Smoke.csproj -c Release` |
| 快照校验 | `z-HistoryDiana` 运行四件齐备且哈希一致 | 见下「快照校验」 |
| 集中发布候选 | 按登记表构建、项目合同/质量门禁、测试、写入 docs、候选 SHA | `.\b-Code\Publish-OneHistoryModule.ps1 -Module HistoryJanus` |
| 集中正式发布 | 候选通过后原子提升含 docs 的 z | 上述命令加 `-Publish`；要从干净 HEAD 复现时另加 `-RequireCleanSource` |
| 集中发布（宿主） | Vulcan 候选、单元测试、质量门禁、公共 API 基线、宿主快照递归 SHA | `.\b-Code\Publish-OneHistoryModule.ps1 -Module HistoryVulcan` |

## Smoke 覆盖的断言

1. 程序集恰好提供 1 个模块入口，模块名 `HistoryDiana`。
2. `ModuleInfo.Version` 与程序集版本一致（不一致会让宿主静默跳过整个模块）。
3. 固定命令必须包含 kit / project / relay 原 13 条，以及 `diana.docs.catalog`。
   通道命令 `diana.docs.<域>` 随现场 z 出现，Smoke 用夹具断言 `diana.docs.janus`，不断言命令总数。
4. 全部命令域为 `HistoryDiana`，类恰为 `docs` / `kit` / `project` / `relay` 四个。
5. 除 `diana.relay.call` 外全部 `Readonly`。
6. 三条基础巡检指令在临时独立仓上校验通过并可执行；对齐指令返回结构化结果，manifest 缺失时明确失败。
7. `diana.docs.catalog` 的对话文本必须含通道命令名；省略 file 只列出本通道；带 file 可读 z 内 Markdown；越出 z 的路径必须失败。
8. 程序集不含 `IUiModule` 实现，不含遗留的 `ProjectPulse` 类型。

摘要行里的命令数与类数**取自实际注册结果**，不写字面量——写死的计数会在增删命令后
悄悄失真，本项目此前就出现过摘要仍写「3 commands」而实际已是 13 条的情况。

## 快照校验

`z-HistoryDiana` 含 `HistoryDiana.dll`、`HistoryDiana.xml`、
`module.manifest.json`、`SHA256SUMS`；发布后另含 `docs/` 中已发布 Markdown。
校验方式：逐行读 `SHA256SUMS`，比对相对路径文件的 SHA-256。

manifest 的 `name` / `version` 必须与 `ModuleInfo` 一致，`ui` 恒为 `false`。

## 部署方式

宿主的模块发现扫描各项目根下的 `z-*` 目录，因此**发布到 `z-HistoryDiana` 即完成部署**，
无需另外拷贝到宿主模块槽。模块部署后由运行中的宿主 `vulcan.module.reload` 热更新；
不要为了换模块关闭 Vulcan。

同名模块出现在多个 z 目录时所有同名候选一起被跳过，因此不得保留 `z-StudioTools` 之类的旧快照。
