# StudioTools V1.1.0 四模块聚合迁移

> 日期：2026-08-01  
> 范围：ActiveDock、ProjectPulse、ToolKit、ToolRelay  
> 排除：GitHubConnection、SE2SW

## 目标

把四个体积较小、同属 Studio 基础设施的模块合并为一个物理源码项目、一个 DLL、一个 OHS 模块槽和一份
发布清单，同时保留原来的四个逻辑模块名与命令名。GitHub 连接治理和 CAD 转换具有独立安全边界与发布节奏，
继续单独维护。

## 结构合同

- 物理项目：`b-Code-StudioTools/StudioTools.csproj`；
- 发布清单：`z-StudioTools/module.manifest.json`；
- 正式槽：`%APPDATA%/OneHistoryStudio/Modules/StudioTools`；
- 逻辑入口：`dock`、`ProjectPulse`、`ToolKit`、`ToolRelay`；
- 命令合同：原四个域和 16 条命令保持不变；
- UI 合同：同一程序集只保留一个 `ActiveDockUiModule` 生命周期；
- AppShell 合同：只通过正式 NuGet feed 固定引用 `OneHistory.AppShell.Core 3.0.3`，不引用 AppShell 源码项目。

AppShell 模块宿主会扫描同一程序集内所有公开 `ModuleInfoBase` 子类，因此一个物理 DLL 可以保留四个逻辑命令域；
公开 `IUiModule` 类型只实例化一次。聚合不需要修改 AppShell 或 OHS 产品代码。

## 迁移与回退

正式迁移前完整备份旧 `ToolKit`、`ProjectPulse`、`ToolRelay` 模块槽。部署时先把旧槽移离 Modules 目录并
执行 `module.reload`，再同步 `StudioTools`，避免相同命令域并存造成注册冲突。聚合模块验收通过后，旧源码和
旧 z 级清单移入 `Unused` 的带时间戳归档，不直接删除。

回退时移离 `StudioTools` 槽，把三份旧槽备份恢复到原名称并执行 `module.reload`。ActiveDock 迁移前没有正式槽，
无需恢复。

## 验收

- Release 构建 0 warning / 0 error；
- Smoke 识别 4 个逻辑入口、16 条命令和 1 个 UI 模块；
- `module.list` 中四个逻辑模块均来自同一个 `StudioTools/StudioTools.dll`；
- `command.show` 验证原命令名、参数和说明保持；
- `tool.list` 只增加一个 `StudioTools` 物理发布项；
- GitHubConnection 与 SE2SW 的源码、清单和正式槽哈希不变。
